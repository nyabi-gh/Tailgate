## 3. 문제점 (버그)

### 3.1 높음

**H1. 뷰어 위에 뜬 로그인 시트에 입력한 글자가 뷰어 단축키로 실행된다** — 코드 확인

- 위치: `src/components/Viewer.svelte:36-54`, `src/lib/actions.svelte.ts:23-28`, `src/lib/actions.svelte.ts:89`.
- 무엇이 문제인가:
  - 로그아웃 상태에서 뷰어의 ♥ 또는 F·↑·↓·S를 누르면 `signedIn()`이 로그인 시트(`<dialog>`의 `showModal`)를 연다.
  - 뷰어는 그대로 떠 있다.
  - 뷰어의 `<svelte:window onkeydown>`은 입력 대상도, 열린 대화상자도 보지 않고 `preventDefault()`까지 한다.
- 결과:
  - 사용자 이름·API 키의 `d` `f` `s` `i` `0`이 입력되지 않는다. API 키는 영숫자라 거의 항상 걸린다.
  - **`d`는 지금 게시물을 실제로 다운로드한다.** 다운로드는 로그인이 필요 없다.
  - ←/→는 뒤의 게시물을 넘긴다.
  - `f`는 시트를 다시 열려 한다.
  - Esc는 시트와 함께 뷰어도 닫는다.
- 근본 원인: 단축키 처리기가 App·Viewer·시트에 따로 `window`에 붙어 있어, 지금 맨 위 계층이 무엇인지 모른다. App 쪽은 `isTyping`을 보지만 Viewer는 보지 않는다.
- 방향:
  - 계층(모달 시트 → 뷰어 → 앱)을 아는 처리기 한 곳으로 모은다.
  - 모달이 열려 있거나 대상이 입력 요소면 아래 계층으로 넘기지 않는다.
  - 열린 시트 뒤에서 ⌘K·`/`가 화면을 바꾸는 문제(`App.svelte:109-116`)도 같은 원인이라 함께 풀린다.

### 3.2 중간

**M1. Mullvad 기기가 지워지거나 계정이 만료되면 "핸드셰이크 실패"로 끝없이 다시 시도한다** — 코드 확인

- 위치: `network.rs:152-157`, `network.rs:439-512`.
  - `is_transient`가 `Tunnel(_)` 전체를 일시적 실패로 본다. `Handshake`도 여기에 들어간다.
- 상황: 사용자가 mullvad.net에서 기기를 지우거나 계정 시간이 끝나면, 서버는 그 키를 버린다. 앱은 이를 확인하지 않는다.
- 매 시도마다 일어나는 일:
  - 핸드셰이크를 10초씩 두 번 기다린다.
  - 서버 목록을 새로 받는다. 몇 초 전에 받은 메모리 사본도 `Origin::Saved`로 취급하기 때문이다.
  - 시도한 서버를 "답하지 않은 서버"로 잘못 뺀다.
- 결과: 최대 60초 간격으로 영원히 반복하고, 화면에는 "핸드셰이크"만 보인다.
- 관련 문제(`network.rs:615-639`): `mullvad_sign_in`은 다음 순서로 진행한다.
  1. 이전 기기를 서버에서 지운다.
  2. 계정 번호를 저장한다.
  3. 기기를 저장한다.
  - 3에서 실패하면 새 기기는 반납하지만, 키체인에는 서버가 모르는 옛 기기가 남아 위와 같은 상태가 된다.
  - 603-604행 문서 주석("모든 단계가 성공해야 저장")도 사실과 다르다.
- 방향:
  - 핸드셰이크가 실패하면 기기 조회(`/accounts/v1/devices/{id}`)와 만료일로 원인을 가린다.
  - 원인은 일시적이지 않은 코드(`deviceRevoked`, `accountExpired`)로 알린다.
  - 계정 번호와 기기를 한 항목으로 저장하거나, 실패하면 되돌린다.

**M2. 첫 실행 규칙이 저장된 WireGuard 설정을 보지 않는다** — 코드 확인

- 위치: `network.rs:420-437`, report.md 6.2절.
- 무엇이 문제인가: `settings.json`에 연결 칸이 없을 때, 키체인의 Mullvad 기기만 보고 없으면 직접 연결로 연다.
- 상황: WireGuard 사용자의 `settings.json`이 사라질 수 있다.
  - 정리 앱이나 재설치.
  - status.md 개발 메모의 "설정 초기화"처럼 파일을 지울 때.
- 결과: 키체인에 `wireguard-config`가 남아 있어도 다음 실행은 직접 연결이다. Mullvad 기기 규칙이 막으려던 바로 그 경우다.
- 방향:
  - `wireguard-config`가 있으면 WireGuard로 시작한다. 둘 다 있을 때의 기준은 문서에 정한다.
  - "WireGuard만 저장된 첫 실행" 테스트를 넣는다.

**M3. 전부 블랙리스트에 걸리는 검색이 결과 끝까지 자동으로 받는다** — 코드 확인

- 위치: `search.rs:23-26`, `search.rs:382-405`, `Grid.svelte:58-61`, `search.svelte.ts:87-104`.
- 원인:
  - `loadMore`가 `$effect` 안에서 `this.loading`을 동기적으로 읽어, effect가 `loading`에 의존하게 된다.
  - 숨긴 게시물은 격자 높이를 늘리지 않는다. 그래서 "끝까지 1.5화면 남음" 조건이 계속 참이다.
  - 그 결과 `loading`이 false가 될 때마다 다시 부른다. 호출당 5페이지 상한은 전체 양을 막지 못한다.
- 예: 로그아웃 상태에서 사이트 기본 블랙리스트에 걸리는 태그(`gore`)를 검색한다.
  - `b<id>` 커서를 끝까지, 초당 1건으로 받는다. 수백 건이 넘을 수 있다.
  - Rust의 `loaded`와 화면의 `#posts`도 계속 커진다.
  - `search.rs:23-26`의 주석("스크롤할 때 그리드가 다시 묻는다")은 사실과 다르다.
- 방향: 보이는 게시물 없는 응답이 N번 이어지면 멈추고 [계속 찾기]를 보인다.

**M4. 블랙리스트 잠금을 네트워크 요청 내내 잡고 있다** — 코드 확인

- 위치: `search.rs:171`(주석), `search.rs:373-418`.
- 무엇이 문제인가: `Searches::next`가 전역 `blacklist` 잠금을 잡은 채 최대 5페이지를 받는다. 이 시간에는 재시도, 30초까지의 `Retry-After`, 30초 읽기 제한이 모두 들어간다.
- 그동안 기다리는 것:
  - 다른 화면의 `next`.
  - 풀·세트 목록의 표지.
  - 창 포커스 때 블랙리스트 다시 받기.
- M3과 겹치면 다른 화면이 한 번에 약 5초씩 막힌다.
- 171행 주석("표시와 기록 사이")은 실제 잠금 범위보다 좁게 설명한다.
- 방향:
  1. 잠금 안에서는 블랙리스트와 세대만 꺼내고 잠금을 푼다.
  2. 페이지를 받는다.
  3. 표시·기록할 때만 다시 잠근다. 그 사이 세대가 바뀌었으면 새 블랙리스트로 다시 판정한다.

**M5. 풀(또는 세트) 두 개를 빨리 열면 나중 것이 닫힐 수 있다** — 코드 확인(타이밍에 따라)

- 위치: `search.rs:205-219`, `search.rs:290-304`, `search.rs:357-363`.
- 원인:
  - `start_pool`은 `api.pool(id).await`가 끝난 뒤에 `open()`을 부른다.
  - `open()`은 순서와 관계없이 같은 화면의 다른 검색을 닫는다.
- 상황:
  1. 풀 A를 누르고 이어서 B를 누른다.
  2. A의 요청이 503 재시도로 늦어져 B가 먼저 열린다.
  3. 늦게 끝난 A가 B를 닫는다.
- 결과: 화면은 B의 id를 들고 있어 `closed`를 받는다. [다시 시도]도 같은 id를 쓰므로, 풀을 다시 열 때까지 멈춘다.
- 방향: await 전에 id를 받고, 같은 화면의 더 새로운 검색(id가 더 큰 것)은 닫지 않는다.

**M6. 계정이 바뀌어도 인기·풀·세트 화면은 그대로다** — 코드 확인

- 위치: `App.svelte:161-178`, `search.rs:421-458`, `blacklistMarks.ts:18-25`.
- 무엇이 문제인가: 계정이 바뀔 때 다시 받는 것은 검색과 즐겨찾기뿐이다.
- 나머지 격자에서 일어나는 일:
  - 이전 계정의 즐겨찾기·투표 표시가 그대로 남는다.
  - 새 계정의 블랙리스트가 이미 받은 게시물에는 적용되지 않는다. 자격 증명이 바뀌면 Rust는 새 세대를 조용히 만들고 `blacklist-changed`를 보내지 않는다.
  - 로그아웃해도 사이트 기본 블랙리스트가 이미 받은 게시물에는 적용되지 않는다.
  - 다음 페이지부터는 새 블랙리스트라, 한 화면 안에서 기준이 섞인다.
- 방향: 자격 증명이 바뀌면 열린 모든 검색을 다시 판정해 `blacklist-changed`를 보내거나, 시작된 모든 목록을 다시 시작한다.

**M7. 뷰어에서 로그인하면 뷰어가 빈 화면으로 남는다** — 코드 확인

- 위치: `App.svelte:168-178`, `viewer.svelte.ts:14-22`, `Viewer.svelte:62`.
- 흐름: 로그인 → 계정 변경 → 검색을 다시 시작 → 목록이 빈다.
- 결과:
  - `viewer.post`는 없는데 `viewer.open`은 참이다. 뷰어는 아무것도 그리지 않지만 키 처리기는 살아 있다.
  - App의 ⌘K·`/`는 `viewer.open`이라 Esc를 누르기 전까지 무시된다.
  - 로그인을 부른 즐겨찾기도 반영되지 않는다.
- 방향:
  - 목록이 다시 시작되면 뷰어를 닫거나, 보던 게시물을 유지한다.
  - 로그인을 부른 동작을 로그인 뒤 이어서 할지도 정한다.

**M8. 즐겨찾기 화면이 새 즐겨찾기를 보여 주지 않는다** — 코드 확인

- 위치: `App.svelte:209-212`, `actions.svelte.ts:31-46`.
- 무엇이 문제인가:
  - 즐겨찾기 목록은 처음 한 번만 받는다.
  - `updatePost`는 이미 받은 게시물만 고친다.
  - 새로 고칠 수단도 없다.
- 결과: 검색에서 ♥한 게시물은 계정을 바꾸거나 앱을 다시 켤 때까지 즐겨찾기 화면에 나오지 않는다.
- 방향:

## 4. 보안·프라이버시

**잘된 점**

- 모든 HTTP 클라이언트가 앱 SOCKS를 거친다: e621, 미디어, 업데이터의 확인과 받기.
- `.proxy()`로 시스템 프록시를 끄고, `socks5h`로 DNS도 터널 안에서 푼다.
- 키는 웹뷰로 가지 않고 `Debug`로 찍히지 않는다.
- `media://`는 `data/` 접두어와 허용 문자만 받고, `..`와 `%`를 거절한다.
- CSP가 엄격하다: `connect-src`는 IPC만, `unsafe-eval` 없음.
- `withGlobalTauri`와 asset 프로토콜이 꺼져 있다.
- 개발자 도구는 디버그 빌드에서 환경 변수를 줄 때만 열린다.

**고칠 것**

**Mullvad API 클라이언트가 시스템·환경 프록시를 따른다**

- 위치: `network.rs:268-274`.
- 무엇이 문제인가: reqwest 기본값대로 `HTTP(S)_PROXY`와 시스템 프록시를 따른다. report.md 6.6절의 "직접 연결"과 다르다.
- 위험: 계정 번호가 `/auth/v1/token`으로 그 프록시를 지난다. 신뢰된 루트 인증서를 가진 TLS 가로채기 프록시라면 읽을 수 있다.
- 방향: `.no_proxy()`를 쓰거나, 의도라면 문서에 적는다.

**루프백 SOCKS에 인증이 없다**

- 위치: `socks.rs`.
- 위험: 같은 컴퓨터의 다른 프로세스나 사용자가 이 터널로 트래픽을 보낼 수 있다. report.md 11절에서 위험으로 인지한 부분이다.
- 방향:
  - 실행마다 임의 비밀번호로 RFC 1929 인증을 건다. reqwest와 업데이터 모두 `socks5h://user:pass@`를 지원한다.
  - 또는 report.md에 적은 사용자 정의 커넥터로 바꾼다.

**업데이트 버전이 서명에 묶이지 않는다**

- 위치: `tauri.conf.json:24-32`.
- 무엇이 문제인가: `requireSignedVersion`(플러그인 2.14에 있고 기본은 꺼짐)을 켜지 않았다.
- 위험: GitHub 계정이나 토큰을 얻은 사람이 `latest.json`에서 높은 버전 번호와 옛 서명 빌드를 짝지어 다운그레이드시킬 수 있다.
- 지금 공개된 두 `.sig`에는 이미 `version:0.1.0`이 들어 있으므로, 켜도 깨지지 않는다.
- 방향: 켠다.

**릴리스가 불변이 아니고, `main`·태그 보호가 없다**

- 위치: 저장소 설정.
- 위험: 공개된 DMG를 바꿔치기할 수 있다. README는 바로 그 DMG의 격리 표시를 지우라고 안내한다.
- 방향:
  - 불변 릴리스를 켠다.
  - `v*` 태그의 삭제와 강제 갱신을 막는 규칙을 둔다.
  - `main`을 보호한다.
  - 산출물에 체크섬과 빌드 증명(attestation)을 붙인다.

**서명 키가 빌드 중 모든 코드에 보인다**

- 위치: `release.yml:60-64`, `release.yml:116-121`.
- 무엇이 문제인가: `TAURI_SIGNING_PRIVATE_KEY`와 암호가 `tauri build`의 환경에 있다.
- 위험: Vite 플러그인과 모든 `build.rs`·proc-macro(크레이트 585개)가 키와 암호를 읽을 수 있다.
- 방향: 키 없이 빌드하고, 새 러너의 별도 작업에서 `tauri signer sign`으로만 서명한다.

**업데이터의 `zip` 기능**

- 위치: `Cargo.toml:29`.
- 무엇이 문제인가: Windows에서만 zip 4.6.1이 들어가고, GitHub advisory 3건(GHSA-m665-v7pm-7grj 외)에 해당한다.
- 실제 노출은 낮다: 플러그인은 서명 검증을 통과한 zip만 풀고, 이 앱은 `-setup.exe`를 그대로 써서 이 기능이 필요 없다.
- 방향: 넣은 이유를 확인한 뒤 기능을 뺀다. 플러그인 2.14.1은 zip을 9.3으로 올린다.

**웹뷰 안 이동을 막지 않는다**

- 위치: `lib.rs:206-237`.
- 무엇이 문제인가: `on_navigation`이 없다. 나중에 웹뷰 안에 링크가 생기면 OS 네트워크로(프록시 밖으로) 로드된다.
- 그 밖에:
  - CSP에 `object-src 'none'`, `base-uri`, `form-action`이 없다.
  - opener가 `http`까지 허용한다.
- 방향: 앱 출처 밖으로의 이동을 거부하고, CSP를 보강하고, opener를 https로 좁힌다.

**의존성 감시와 보고 경로가 없다**

- 위치: 저장소.
- 없는 것:
  - Dependabot이 꺼져 있고 `dependabot.yml`도 없다. SHA로 고정한 액션이 갱신되지 않는다.
  - CI에 `cargo audit`, `cargo deny`, `npm audit`이 없다.
  - `SECURITY.md`가 없고, 비공개 취약점 보고가 꺼져 있다.
- 개발 의존성 npm audit 결과: vitest 중간 1건(4.1.12에서 고침), deepmerge 낮음 1건.
- 방향: Dependabot(cargo·npm·actions), `cargo-deny`, `SECURITY.md`.

## 5. 배포·운영

### 5.1 높음: 설치본과 Windows 업데이트를 한 번도 실행하지 않고 공개했다

- v0.1.0을 두 번 모두 설치 확인 없이 공개했다(status.md 16-17행).
- Windows NSIS `passive` 업데이트 경로와 Windows 실기기 동작 전체가 확인되지 않았다(status.md 122·147행).
- 위험: Windows 0.1.0의 업데이터가 동작하지 않으면 Windows 사용자는 0.1.0에 갇히고, 알릴 방법도 없다. 앱 안 업데이트가 유일한 경로다.

0.1.1을 공개하기 전에 할 것:

- 초안 산출물을 Windows(VM이라도)에 설치한다.
- 0.1.0 → 0.1.1 업데이트를 끝까지 해 본다. 테스트 저장소나 로컬 `latest.json`을 쓴다. status.md 개발 메모의 로컬 업데이트 방법을 Windows에도 적용하면 된다.
- 배포 워크플로에 앱이 뜨는지 보는 단계를 더할지 검토한다.

### 5.2 높음: 서명 키가 단일 장애점이다

- 키를 한 번 잃었다(첫 키 `8DFE…`).

### 7.1 고칠 것 (3절 버그 외)

**명도 대비가 모자라다** (계산)

- `--faint`(라이트 `#A0A4AB`, 다크 `#5D626B`)가 글자에 쓰이는데, 대비가 2.1~2.9:1이다. 기준은 4.5:1이다.

- 방향: 글자는 `dim`으로 쓰고, `faint`는 아이콘과 선에만 쓴다.

**select에 포커스 표시가 없다**

### 7.2 개선 제안

- **뷰어 첫 화면**: 샘플을 받는 동안 빈 화면이고, View Transition도 빈 상자로 커진다. 이미 받은 미리보기를 확대해 깔고, 그 위에 샘플을 올린다.
- **키보드로 격자 다루기**: 화살표로 이동(roving focus), Enter로 열기, 닫으면 마지막에 본 썸네일로 포커스.
- **단축키 알리기**:
  - 뷰어 버튼의 `title`에 ←/→/Esc/I가 없다.
  - "?"로 단축키 목록을 연다.
  - ⌘1~5로 사이드바 화면, ⌘,로 설정(macOS 관례).
  - ⌘R로 지금 화면을 새로 고친다(M8과 함께).
- **다운로드 진행**: 지금은 그 게시물의 정보 패널에만 보인다. 사이드바나 알림에도 보인다.
- **연결 실패 안내**: 본문에서도 보인다(M9).
- **썸네일 해상도 기준**: `isLargeCell`의 240px 기준은 Retina에서 정한 고정값이다. `devicePixelRatio`를 반영하면 1x 화면에서는 `sample` 요청을 줄이고, 2x에서는 기준을 다시 잴 수 있다(status.md에 "240px 기준 실측 안 함"이 남아 있다).
- **Windows**: 신호등 여백을 없애고, 뷰어 끌기 영역을 조정한다(3.3).

- `.gitignore`에 `*.key`와 `.env*`가 없다. 서명 키를 다루는 저장소라 넣어 두는 편이 안전하다.
- 설계 문서가 한국어로만 되어 있어 외부 기여자는 읽기 어렵다. 의도라면 그대로 둔다.
