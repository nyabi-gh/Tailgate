# 진행 상황

2026-10-21 기준. 계획은 [report.md](report.md), 근거는 [research.md](research.md). 상태는 이 문서에만 적는다.

## 지금 단계

1단계 1~10번의 코드를 모두 작성하고 커밋했다(2026-10-21). 남은 것은 사용자가 손으로 해 보는 확인(아래 "남은 일"), 푸시, 1단계 11번(배포)이다.

- **1~8번**(공개 저장소 https://github.com/nyabi-gh/Tailgate 에 올림): 터널·킬 스위치·`media://`(동영상 블록 캐시), API 계층, 계정(로그인·키체인), 검색(태그 칩·자동완성·정렬·3:4 격자·가상/무한 스크롤), 블랙리스트(e621 사이트와 같은 규칙), 뷰어(전환 효과·줌·원본·GIF·동영상·정보 패널), 즐겨찾기·투표·다운로드와 즐겨찾기 화면.
- **9번 연결 설정**: 설정 화면의 계정·연결 칸, 직접 / WireGuard 파일 / Mullvad 로그인·위치 선택, 서버 목록 디스크 캐시, 실행 중 끊김 감지·자동 재연결, 라우트 전환 시 연결 끊기. 같은 날 검색 화면이 태그 없이 최신 게시물로 열리게 바꿨다(따로 홈 버튼 없음, report.md 3절).
- **터널 직후 `TtlExpired`**: 원인을 재현으로 확인했다(research.md 7절). 같은 Mullvad 기기 키로 터널이 둘 떠 있으면 먼저 연결한 쪽이 응답을 받지 못한다. 앱을 한 번에 하나만 실행되게 하고, WireGuard 파일 칸에 안내를 넣었다. 조사 중 `jp-tyo-wg-002`가 핸드셰이크에 전혀 답하지 않는 것을 찾아, 답하지 않은 서버는 실행 중 후보에서 빼고 바로 다른 서버로 다시 시도하게 했다. 터널 패킷 로그(`RUST_LOG=tunnel_packets=trace`)를 남겼다.
- **10번 설정**(report.md 12절의 네 단계): 10-1 설정 파일의 일반 칸·언어 선택·18세 확인, 10-2 칸 폭 기억·최근 검색어·블랙리스트 다시 받기, 10-3 다운로드 폴더·파일 이름 규칙, 10-4 이미지 디스크 캐시·비우기. 설정 화면 칸 순서는 일반 / 계정 / 연결 / 보기 / 다운로드 / 저장 공간.
- **푸시 안 함**: `origin/main`은 2f6c25f이고, 548d894부터 그 뒤의 커밋은 모두 로컬에만 있다.

## 남은 일

- **사용자 확인(9·10번)**: 아래 9번 항목과, 10번의 18세 확인·언어·최근 검색어·썸네일 크기·다운로드 칸·저장 공간 칸 항목. 9번: 방식 바꾸기(직접으로 바꾸면 e621이 막히는지, 다시 Mullvad), 위치 바꾸기, "다시 연결", e621 로그아웃·로그인(설정 칸에서), Wi-Fi를 3분 넘게 껐다 켜서 끊김 감지·자동 재연결, 재연결 뒤 썸네일 다시 받기. Mullvad 로그아웃·로그인(기기 `divine condor`가 지워지고 새 기기가 등록됨)과 `.conf` 가져오기(mullvad.net에서 만들면 기기 칸을 하나 씀)는 원할 때만.
- 끊김 감지는 테스트로 고정하지 못했다(실제 WireGuard 상대가 필요). 실제 앱에서 Wi-Fi를 끄는 방법으로만 확인한다. macOS 잠자기 동안 단조 시계가 멈추는 경우의 동작도 확인하지 않았다.
- 18세 확인 화면의 다크 모드, 저장하지 못했을 때의 알림, 실제 버튼 클릭([18세 이상입니다], [종료])과 설정 화면의 언어 버튼 클릭은 손으로 해 보지 않았다(임시 코드로 같은 함수를 불렀다). 최근 검색어 목록의 클릭·키보드 선택, 설정 화면의 썸네일 크기 슬라이더와 [지우기]도 같다. 사용자 확인 때 함께 본다.
- 저장 공간 칸(사용량 표시, [비우기], 최대 크기 바꾸기)은 화면으로 보지도, 손으로 해 보지도 않았다(확인 도중 사용자 요청으로 멈춤). 최대 크기를 낮췄을 때 실제 폴더가 줄어드는 것도 테스트로만 확인.
- **다음 세션 시작 때 전체 검사를 한 번 돌린다.** 10-4는 사용자 요청으로 중간 커밋을 따로 빌드하지 않았고, 마지막 상태도 디스크 응답 디버그 로그 한 줄을 넣은 뒤로는 컴파일만 했다.

- 자동완성 결과가 하나도 없을 때의 응답 모양은 아직 못 봤다(`zzzzqqqq`도 비슷한 태그가 와서 빈 결과가 안 나옴). 지금 코드는 배열만 받는다. `tags.json`은 빈 결과가 `{"tags":[]}`라 다를 수 있다.
- 태그 입력·자동완성·정렬 메뉴·⌘K는 실제 앱에서 손으로 써 보지 못했다(키 입력 자동화 권한 없음). 앱 밖 브라우저에서는 명령이 없어 자동완성이 안 뜬다. 사용자 확인이 필요하다.
- 검색 화면의 다크 모드는 아직 못 봤다(시스템이 라이트 모드).
- 썸네일 해상도 기준(칸 폭 240px)은 실제로 재 보지 않았다. 한 페이지 썸네일이 다 뜨는 시간은 재지 못했다(이미지 완료 시점이 로그에 없음).
- 로그인 시트의 다크 모드와 오류 표시는 실제 앱에서 아직 못 봤다(시스템이 라이트 모드, 앱 밖 브라우저에서는 명령이 없어 오류를 띄울 수 없음). 오류 경로는 테스트로만 확인.
- 탐색 반응 시간을 창이 앞에 있는 상태로 다시 잰다(가려진 창에서는 WebKit이 미디어 로딩과 타이머를 멈춘다). 부족하면 report.md 7.2절의 첫 블록 축소·동시 받기를 검토한다. 확인용 임시 패널은 커밋하지 않는다. `canLoadRemote()`가 참일 때만 `mediaUrl(...)`로 `<video>`를 띄운다(예: 게시물 6791442의 720p 샘플, 6791860의 3분 MP4).
- 단일 실행을 Windows에서 확인하지 못했다(두 번째 실행이 끝나고 기존 창이 앞으로 오는지).
- 같은 `.conf`를 다른 WireGuard 앱과 함께 쓰는 충돌은 안내만 하고 감지하지 않는다. gotatun이 모르는 세션의 패킷을 신호 없이 버려서 감지하려면 우회가 필요하다.
- `jp-tyo-wg-002`가 다른 기기(공식 Mullvad 앱)에서는 붙는지 확인하면 우리 기기 키만의 문제인지 가릴 수 있다(원할 때만).
- 터널 시작이 5.3초 걸린 1회(첫 핸드셰이크 재전송으로 보임)가 다시 나오는지 지켜본다.
- 터널 안 연결이 리셋되거나 timeout으로 끊기면 읽기가 오류가 아니라 EOF로 끝난다. 지금은 모든 요청이 TLS라 잘림이 오류로 드러나지만, 평문 요청을 쓰게 되면 `netstack.rs`에서 구분해야 한다.

## 개발 메모

- API 수동 점검: `cd src-tauri && cargo run --example api_probe -- [태그]`. 앱과 같은 경로(저장된 기기면 터널)로 me, 검색 2페이지, `order:score`, WebM, 삭제된 게시물, 단일 게시물, 자동완성을 부른다. e621 응답 구조가 바뀌면 여기서 디코딩 오류로 드러난다.
- 터널 수동 점검: `cd src-tauri && cargo run --example tunnel_probe` (`--forget`은 Mullvad 기기 등록 해제, `PROBE_DOWNLOAD=<url>`은 속도 측정, `--serve`는 SOCKS5를 열어 두어 `curl -x socks5h://<주소>`로 터널을 쓸 수 있다). 출력의 "tunnel up in"은 이제 핸드셰이크까지 포함한다. 디버그·릴리스 실행 파일은 각각 처음 키체인을 읽을 때 허용 창이 뜬다.
- Mullvad 계정 번호는 사용자가 직접 넣는다: `security add-generic-password -s pro.tb.nyabi.Tailgate -a mullvad-account -w`. 이 계정에는 지금 `divine condor` 기기가 등록되어 있다.
- 키체인 항목을 다른 실행 파일이 만들었거나 다시 빌드한 디버그 실행 파일이 읽으면 macOS가 접근 허용 창을 띄운다. 창이 떠 있는 동안 앱은 `connecting`으로 기다리고, 거부하면 `failed`(`credentialStore`)로 막힌 채 남는다.
- 디버그 로그: `RUST_LOG=info,tailgate_lib=debug npm run tauri dev`. 웹 인스펙터는 `TAILGATE_DEVTOOLS=1`(디버그 빌드에서만).
- 검사: `cargo test`, `cargo clippy --all-targets`, `cargo fmt --check`(`src-tauri`), `npm test`, `npm run check`, `npm run build`. Svelte 경고는 `npm run check`가 아니라 `npm run build`에서만 나오는 것이 있으니 둘 다 본다.
- 클릭·입력이 필요한 화면 확인은 사용자가 개발 앱에서 직접 한다. 꼭 필요할 때만 커밋하지 않는 임시 자동 실행 코드(`// TEMP verification`)를 `App.svelte`에 넣고 확인 뒤 지운다. 창이 다른 창에 가려지면 WebKit이 타이머와 미디어를 멈추니 그동안 창을 앞에 두어야 한다.
- 이미지 디스크 캐시는 `~/Library/Caches/pro.tb.nyabi.Tailgate/media/`. 디스크에서 응답한 요청은 디버그 로그에 `media <경로> from disk`로 남는다. 처음 상태로 보려면 앱을 끄고 이 폴더를 지운다.
- 다운로드는 기본으로 `~/Downloads/Tailgate`에 저장된다. 설정 화면에서 폴더와 이름 규칙을 바꾸면 `settings.json`의 `downloads`에 남는다.
- **앱이 연결된 동안 `tunnel_probe`·`api_probe`를 돌리지 않는다.** 같은 기기 키라 먼저 연결한 쪽이 응답을 못 받는다(research.md 7절). 앱도 두 개 띄울 수 없다(개발 앱과 설치본 포함).
- 터널 패킷 보기: `RUST_LOG=info,tunnel_packets=trace,smoltcp=trace`(gotatun까지 보려면 `gotatun=trace`). 오가는 IP 패킷과 smoltcp의 DNS·TCP 상태가 찍힌다. 응답이 아예 안 오는 문제는 이것으로 구분한다.
- 연결 설정을 처음 상태로 되돌리려면 앱을 끄고 `settings.json`을 지운다(첫 실행 규칙을 다시 탄다. 18세 확인과 언어도 처음 상태가 된다). 서버 목록 캐시는 `relays.json`을 지우면 다음 연결에서 새로 받는다.
- 원격 저장소: `origin` = https://github.com/nyabi-gh/Tailgate (공개). 공개 저장소 생성 같은 명령은 권한 검사에 막혀 사용자가 직접 실행했다.
- 화면 확인: 키 입력 자동화(손쉬운 사용) 권한은 없고 화면 기록 권한은 있다. 창 캡처는 `CGWindowListCopyWindowInfo`로 창 번호를 찾아 `screencapture -l <번호>`. CSS 계산값은 작은 Swift 프로그램으로 WKWebView에 빌드된 CSS를 띄워 `getComputedStyle`로 잰다.
