# Tailgate 구현 계획

Windows·macOS용 e621 뷰어. 다른 사람에게도 배포한다.

- 이 문서는 **무엇을 어떻게, 왜 그렇게 만드는지**를 적는다. 자주 바뀌지 않는다.
- 어디까지 됐고 다음에 무엇을 하는지는 [status.md](status.md)에만 적는다.
- 근거가 된 조사·실측은 [research.md](research.md)에 있다. 본문의 "research.md N절"은 그 문서를 가리킨다.

## 1. 개요

**Tauri 2(Rust) + Svelte 5(TypeScript) + Tailwind CSS v4 + 앱 내장 WireGuard 터널.**

| 맡는 쪽 | 하는 일 |
|---|---|
| Rust | API 호출·스로틀·인증, 블랙리스트, 다운로드, 터널, 미디어 파일 받기 |
| 웹뷰 | 화면 그리기. Rust가 넘겨준 미디어를 표시·재생한다(GIF·동영상 디코딩은 웹뷰 몫) |

앱의 외부 요청은 모두 Rust에서 나가고, 앱 안의 SOCKS5 프록시와 (설정했다면) 터널을 거친다.

- **API는 Rust에서만 부른다.** 웹뷰가 부르면 브라우저 UA가 나가서 e621 규칙(전용 UA)을 어기고, 스로틀을 우회하는 경로가 생긴다. API 키는 사용자가 로그인 시트에 입력하는 순간에만 웹뷰에 있고, 보낸 뒤 입력값을 지운다. 그 뒤로는 Rust만 갖는다.
- **미디어도 Rust가 받아 `media://`로 넘긴다.** static1은 웹뷰의 cross-site 요청을 핫링크로 보고 403을 준다(research.md 7절). 웹 페이지는 그 헤더를 바꿀 수 없다.

## 3. 기능 범위

### 1단계 (MVP)
- **계정**: 사용자명 + API 키 로그인, `/users/me.json`으로 확인, 로그아웃. 로그인 없이도 둘러보기 가능.
- **검색**: 태그 입력(자동완성, 입력한 태그를 카테고리 색으로 표시), 정렬 메뉴, 최근 검색어.
- **그리드**: 같은 크기의 3:4 세로형 칸에 그림을 꽉 채워(잘라) 넣는 격자, 가상 스크롤, 무한 스크롤, 썸네일 크기 조절(Ctrl/⌘ + 휠 또는 슬라이더). 처음에는 원본 비율을 지키는 행 정렬(justified)이었으나, 칸마다 폭이 달라 어수선하다는 사용자 의견으로 2026-10-21에 바꿨다. 그림 전체는 뷰어에서 본다.
- **뷰어**: 창 전체를 덮는 뷰어. 이미지는 샘플을 먼저 띄우고 원본은 확대하거나 요청할 때 받음. 줌·패닝, GIF, 동영상(MP4 우선) 반복 재생. 오른쪽 패널에 메타 정보와 카테고리별 태그.
- **키보드**: ←/→ 이전·다음, Esc 닫기, F 즐겨찾기, ↑/↓ 투표, / 검색창, D 다운로드.
- **즐겨찾기·투표**, 내 즐겨찾기 목록.
- **블랙리스트**: 계정의 블랙리스트를 Rust에서 평가해 걸러 냄. "N개 숨김"을 누르면 잠시 보이게 함.
- **다운로드**: 원본을 지정 폴더에 저장(파일명 규칙 설정 가능, 예: `{id}_{artist}.{ext}`). 저장 대화상자 대신 기본 폴더로 바로 저장.
- **연결**: 직접 연결 / WireGuard 설정 파일(.conf 가져오기) / Mullvad 계정(서버 위치 선택). 연결 상태를 사이드바 아래에 표시.
- **설정**: 계정, 연결, 다운로드 폴더와 파일명 규칙, 썸네일 크기, 캐시 비우기, 언어.
- **자동 업데이트**: 다른 사람에게 배포하므로 1단계에 넣는다.
- **18세 이상 확인**: 처음 실행할 때(e621 약관).

### 2단계
- 태그 클릭으로 재검색, 우클릭 메뉴(검색에 추가/제외/새 탭에서 검색)
- 검색 탭 여러 개(창 상단 탭)
- Pool 목록과 순서대로 읽는 리더
- Set 목록·열람·추가/빼기
- 댓글과 DText 렌더링
- 인기 게시물

### 3단계 (필요해지면)
- 저장한 검색(사이드바 고정), 댓글 작성, 일괄 다운로드(풀 전체 등, API 스로틀 준수)

## 4. 구조

Tauri 기본 구조에 폴더만 나눈다. Cargo 워크스페이스나 크레이트 분리는 하지 않는다. 빌드가 느려지면 그때 `api`를 크레이트로 뗀다. 파일마다 구현됐는지는 status.md에 적는다.

```
tailgate/
  src-tauri/
    src/
      main.rs            진입점
      lib.rs             Tauri 빌더, 창 생성(플랫폼별 옵션), 상태 조립, 이벤트 연결
      commands.rs        프런트엔드에 노출하는 명령 (얇게: 검증 → 호출 → 반환)
      network.rs         SOCKS 프록시와 터널 소유, 연결 상태(watch)와 실패 코드, e621용 HTTP 클라이언트
      media/
        mod.rs           media:// 프로토콜: static1 data/ 경로만, 앱 연결로 받아 응답, Range 처리
        blocks.rs        동영상 블록 캐시 (1MB 블록, LRU)
      secrets.rs         OS 키체인 (keyring-core + 플랫폼 저장소)
      tunnel/
        mod.rs           Tunnel::start(핸드셰이크까지)/stop. 밖에서는 이것만 쓴다
        config.rs        WireGuard .conf 파서 → TunnelConfig
        mullvad.rs       토큰, 기기 등록/삭제, 서버 목록 → TunnelConfig
        wg.rs            gotatun Device에 smoltcp 패킷 큐를 꽂는 IpSend/IpRecv 어댑터
        netstack.rs      smoltcp 인터페이스, async TcpStream, 터널 안 DNS
        socks.rs         127.0.0.1 SOCKS5 서버, Route(Direct/Tunnel/Blocked)
      api/
        mod.rs           Api, ApiError(오류 코드. 프런트엔드에는 코드와 값만 보내고 문구는 프런트엔드 몫)
        client.rs        e621 요청, UA, Basic 인증, 스로틀, 재시도
        models.rs        e621 원본 응답(serde) → 앱 모델 정규화
        endpoints.rs     posts, users/me, autocomplete, PostSearch(페이지 넘김) … (favorites, votes는 8번)
      search.rs          열린 검색(PostSearch)들, 검색어 태그의 카테고리를 결과에서 찾기
      blacklist.rs       파서 + 평가기
      account.rs         API 키 저장/삭제(키체인 `e621-account`), 로그인·로그아웃, 시작 시 복원·확인, 401 처리, 계정 상태(watch)
      settings.rs        설정 JSON (앱 설정 디렉터리)
      download.rs        원본 다운로드, 파일명 규칙
    examples/
      tunnel_probe.rs    실제 Mullvad 서버로 터널을 검증하는 수동 점검 도구
      api_probe.rs       앱과 같은 경로로 실제 e621 API를 불러 응답 구조를 확인하는 수동 점검 도구
    tests/fixtures/      Pawru 픽스처 재사용 (실제 응답 JSON)
  src/                   Svelte 5 + TypeScript
    lib/
      connection.svelte.ts  연결 상태 (명령 + 이벤트 구독), canLoadRemote()
      account.svelte.ts  계정 상태 (명령 + 이벤트 구독), signIn/signOut
      media.ts           static1 URL → media:// 주소, 썸네일/샘플/원본/동영상 선택
      platform.ts        OS 판별, 단축키 표기
      i18n/              en.ts(기준), ko.ts, 현재 언어 상태
      views.ts           사이드바 화면 목록
      ipc.ts             invoke 래퍼 (명령 이름·타입을 한곳에)
      layout.ts          격자 계산(열 수·칸 크기·보이는 범위), 썸네일 크기 범위 (순수 함수, vitest)
      search.svelte.ts   검색 상태 (시작·다음 페이지·다시 시도), 알게 된 태그 카테고리
      posts.ts           Rust 모델의 TS 타입, API 오류 코드
      tags.ts            태그 토큰 해석(제외·메타태그), 카테고리 색
      keys.ts            키보드 단축키
    state/               검색, 계정, 설정 상태 (Svelte runes 모듈)
    views/               Search, Viewer, Favorites, Settings, Login
    components/          Sidebar, SearchField, EmptySearch, Grid, Thumb, TagInput, TagList …
    styles/app.css       Tailwind 진입점, 디자인 토큰(CSS 변수 + @theme), 기본 스타일
```

원칙:
- **로직은 Rust, 화면은 Svelte.** 블랙리스트, 페이지네이션 커서, 응답 정규화, DText 파싱(2단계)은 Rust에서 하고 `cargo test`로 고정한다. 프런트엔드 테스트는 `layout.ts`처럼 순수 함수만 두고 vitest(`npm test`)로 돌린다.
- Repository 계층, DI 컨테이너, 상태 관리 라이브러리는 쓰지 않는다. 상태는 Svelte runes 모듈 몇 개면 충분하다.
- Rust↔TS 타입은 처음에는 손으로 맞춘다(모델이 10개 안팎). 어긋나는 일이 생기면 `ts-rs`로 생성하는 방식으로 바꾼다.
- Rust 코드는 `cargo fmt`(기본 설정)와 `cargo clippy`를 통과시킨다.

## 5. 데이터 흐름

```
Svelte 화면 → ipc.ts → invoke("next_page", {search})
  → commands.rs → PostSearch(검색마다 하나) → api::client
      스로틀(요청 시작 간격 최소 1초. 응답을 기다리는 동안 다음 요청이 막히지는 않는다)
      UA "Tailgate/<버전> (by <user> on e621)", Authorization: Basic …
      401 → 로그아웃 상태 전환 / 429·503 → Retry-After(30초 이하) 또는 1·2·4초 백오프(최대 3회) / 410 → 끝
  → serde 디코딩·정규화 → 블랙리스트 평가 → { posts, hidden_count, done }
  → 화면이 <img src="media://localhost/data/…">로 표시 (Windows는 http://media.localhost/data/…)
  → media.rs가 앱 연결(SOCKS → 직접 또는 터널)로 static1에서 받아 응답
```

- **페이지 넘김**: 검색 하나가 Rust의 `PostSearch` 하나다(태그, 다음 페이지, 이미 돌려준 id). 태그에 `order:`가 없으면 `page=b<받은 것 중 가장 작은 id>`, 있으면 `page=N`(750까지). 한 페이지는 100개이고, 그보다 적게 오면 끝이다. 프런트엔드는 검색 id만 들고 있는다. 처음에는 불투명한 커서 문자열을 주고받으려 했지만, 중복 제거에 id 집합이라는 상태가 필요해 Rust가 검색 상태를 갖기로 했다(2026-10-19).
- **한 페이지가 전부 블랙리스트로 숨겨지면** `PostSearch`가 다음 페이지를 이어 받는다(최대 횟수 제한, 6번).
- **중복 제거**: `PostSearch`가 돌려준 id 집합으로 거른다. 페이지 번호 방식에서 게시물이 다음 페이지로 밀려 다시 오는 경우다.
- **미디어 선택**(`media.ts` 한곳): 썸네일은 `preview`, 칸 폭이 240px 이상이면 `sample`(폭 256px 미리보기가 Retina에서 눈에 띄게 흐려지는 크기. `sample`은 몇 배 크므로 그때만), 뷰어는 `sample` → 원본은 요청/확대 시 `file`. 동영상은 `720p` → `480p` → `variants.mp4` → 원본 WebM 순. URL이 null이면 플레이스홀더.
- **원격 미디어는 연결이 준비된 뒤에만 요청한다.** 준비 전 요청은 킬 스위치에 막혀 실패하고, 웹뷰가 실패를 기억해 다시 요청하지 않는다. 화면은 `connection.svelte.ts`의 `canLoadRemote()`를 보고 렌더링한다.

## 6. 연결 (앱 내부 전용 VPN)

### 6.1 구조

```
            ┌──────────────────── Tailgate 프로세스 ─────────────────────────────────┐
 웹뷰 ──media://──▶ media.rs ─┐                                                     │
            │                 ├─▶ reqwest ─socks5h─▶ socks.rs ─▶ netstack.rs(smoltcp) ─IP─▶ wg.rs ⇄ gotatun Device ─┼─UDP─▶ WireGuard 서버 ─▶ e621
 화면 ─invoke─▶ api(예정) ─────┘                                                     │
            └──────────────────────────────────────────────────────────────────────┘
```

- **권한 상승이 필요 없다.** OS에 VPN 인터페이스를 만들지 않으므로 다른 앱과 시스템 라우팅에 영향이 없다.
- **WireGuard 프로토콜 처리(핸드셰이크·재키잉·keepalive)는 gotatun의 `Device`가 한다.** OS TUN 대신 `with_ip_pair`로 smoltcp와 패킷을 주고받는 어댑터(`wg.rs`)만 우리가 쓴다.
- **웹뷰는 외부로 직접 요청하지 않는다.** 그래서 웹뷰 프록시 설정(`proxy_url`)이 필요 없고, 루프백 SOCKS는 Rust의 HTTP 클라이언트만 쓴다.

### 6.2 연결 방식

설정 > 연결 화면은 1단계 9번에서 만든다.

- **직접 연결**: SOCKS가 그냥 직접 연결한다.
- **WireGuard 설정 파일**: 표준 `.conf`를 가져온다(`PrivateKey`, `Address`, `DNS`, 피어의 `PublicKey`, `PresharedKey`, `Endpoint`, `PersistentKeepalive`). 첫 `[Peer]`만 쓴다. `AllowedIPs`는 앱 트래픽 전체를 보내므로 무시한다. 터널 안 DNS가 꼭 필요하므로 `DNS`가 없는 설정은 거절한다.
- **Mullvad**: 계정 번호 → 토큰 → 앱이 키 쌍을 만들어 기기로 등록 → 받은 터널 주소와 서버 목록으로 설정을 만든다. 서버는 국가/도시로 고른다(지금은 `jp-tyo` 고정). 로그아웃하면 기기 등록을 지운다.
- **지금의 임시 규칙**: 키체인에 Mullvad 기기(`mullvad-device`)가 있으면 터널, 없다고 확인되면 직접 연결. 설정 화면이 생기면 설정 파일에 저장한 방식을 따른다.

### 6.3 킬 스위치

트래픽이 의도하지 않은 경로로 나가지 않게 하는 규칙이다. 1·3은 `network.rs`의 테스트로 고정한다(목 키체인으로 오류를 넣고, 로컬 서버에 요청이 닿는지 본다).

1. **프록시는 막힌 채(`Blocked`)로 시작한다.** 저장된 설정을 읽어 직접 연결이라고 확인된 경우에만 `Direct`로 연다. 키체인을 읽지 못했거나(접근 거부, 잠김) 저장 값이 깨졌으면 막힌 채로 두고 `failed`를 알린다. 오류를 "설정 없음"으로 취급하지 않는다.
2. **터널은 WireGuard 핸드셰이크가 끝난 뒤에만 연다.** gotatun 장치를 만드는 것만으로는 서버에 닿는다는 보장이 없다(research.md 8절). 핸드셰이크가 끝나야 라우트를 `Tunnel`로 바꾸고 `tunnel` 상태를 알린다.
3. **실패하면 `Blocked`로 남는다.** 터널 모드에서 직접 연결로 넘어가는 코드 경로는 없다.
4. **라우트를 바꾸면 그 전 라우트로 중계 중인 연결을 모두 끊는다.** 라우트는 SOCKS 연결을 맺을 때 정해지므로, 그대로 두면 reqwest가 풀에 둔 연결을 계속 써서 옛 경로로 트래픽이 나간다. 지금은 라우트가 시작할 때 `Blocked`에서 한 번만 바뀌고 막힌 연결은 풀에 남지 않아 문제가 없다. 실행 중 전환(연결 방식 바꾸기, 끊김 감지)을 넣는 1단계 9번에서 함께 구현한다.
5. **실행 중 끊김을 감지하면 `Blocked`로 바꾸고 `failed`를 알린다**(1단계 9번). gotatun 피어 통계의 `last_handshake`가 재키잉 주기를 넘도록 갱신되지 않거나 `Device::wait()`가 치명적 오류를 알리면 끊긴 것으로 본다. 그다음 다시 연결을 시도한다.

### 6.4 연결 상태

| 상태 | 뜻 | 원격 요청 |
|---|---|---|
| `connecting` | 시작 직후. 저장된 설정을 읽거나 터널을 세우는 중 | 막힘 |
| `direct` | 직접 연결 | 허용 |
| `tunnel {relay}` | 핸드셰이크까지 끝난 터널. `relay`는 서버 호스트 이름 | 허용 |
| `failed {code}` | 실패. 막힌 채로 남는다 | 막힘 |

- Rust가 `watch` 채널로 갖고, 바뀌면 `connection-changed` 이벤트를 보낸다.
- 화면은 이벤트를 먼저 구독한 뒤 `connection_status` 명령으로 첫 값을 읽는다. 이벤트와 명령 응답은 서로 다른 경로로 와서 순서가 보장되지 않으므로, 응답보다 이벤트가 먼저 왔으면 응답을 버린다.

실패 코드. 화면이 언어별 문구로 바꾼다(9절). 자세한 원인은 Rust 로그에만 남긴다.

| 코드 | 원인 |
|---|---|
| `credentialStore` | 키체인을 읽지 못함(접근 거부, 잠김) |
| `savedDevice` | 저장된 Mullvad 기기 정보가 깨짐 |
| `relayList` | Mullvad 서버 목록을 받지 못함 |
| `noRelay` | 고른 위치에 활성 서버가 없음 |
| `tunnel` | 터널을 세우지 못함(서버 주소, 키, UDP 소켓) |
| `handshake` | 서버가 핸드셰이크에 답하지 않음 |

### 6.5 타임아웃

연결이 죽었을 때 요청이 끝없이 기다리지 않고 오류로 끝나게 한다.

| 대상 | 값 | 비고 |
|---|---|---|
| WireGuard 핸드셰이크 | 10초 | gotatun은 5초(+지터)마다 다시 시도한다. 한 번 더 시도할 여유를 둔다 |
| 터널 안 DNS | 10초 | |
| 터널 안 TCP 연결 | 15초 | |
| 터널 안 TCP 무응답 | keep-alive 15초, 상대 패킷이 45초 없으면 끊음 | smoltcp는 keep-alive만으로는 연결을 끊지 않는다(research.md 8절) |
| e621 HTTP | 연결 30초, 읽기 간격 30초 | 연결 값은 터널 안 DNS + TCP 연결 한도(25초)보다 길게 둔다. 전체 시간 제한은 큰 원본 다운로드를 끊으므로 두지 않는다 |
| Mullvad API | 요청 전체 30초 | 약 600KB인 서버 목록 포함 |

### 6.6 그 밖의 규칙

- **DNS도 터널 안에서 푼다.** SOCKS5에 도메인 이름째로 넘기고(`socks5h`), 설정의 `DNS`(Mullvad는 `10.64.0.1`)로 smoltcp DNS 소켓이 조회한다.
- **Mullvad API 호출은 직접 연결로 한다.** 터널을 세우기 위한 호출이기 때문이다.
- **비밀 값**: WireGuard 개인 키(기기 정보 JSON 안)와 Mullvad 계정 번호는 OS 키체인에 저장한다. 서비스 이름은 `pro.tb.nyabi.Tailgate`, 항목은 `mullvad-account`, `mullvad-device`. 키체인 읽기는 macOS 접근 허용 창을 기다릴 수 있으므로 메인 스레드가 아닌 블로킹 작업 스레드에서 한다. 그동안 창은 `connecting`으로 뜬다.
- **smoltcp 난수 시드는 실행마다 OS 난수로 채운다.** TCP 초기 순서 번호와 DNS 질의 ID가 이 시드에서 나오는데, 기본값 0이면 실행할 때마다 같은 값이 반복된다(research.md 8절).
- 터널은 IPv4만 다룬다(smoltcp 인터페이스, DNS A 레코드).

## 7. 미디어와 캐시

### 7.1 `media://`

- static1의 `data/` 경로만 받는다. 다른 경로와 `..`, 퍼센트 인코딩은 404로 거절해 임의 URL 요청 통로가 되지 않게 한다.
- 주소: macOS `media://localhost/data/…`, Windows `http://media.localhost/data/…` (`media.ts`가 만든다).
- 받은 상태 코드와 `Content-Type`, `Content-Range`, `Accept-Ranges`를 그대로 넘긴다. `Content-Length`는 wry가 붙인다(macOS에서 확인).

### 7.2 동영상 블록 캐시

WKWebView는 커스텀 프로토콜의 MP4를 8~24바이트짜리 Range로 수백 번 읽는다(research.md 7절). 요청마다 static1로 왕복하면 재생이 시작되지 않으므로, 블록 단위로 받아 두고 작은 Range는 캐시에서 응답한다.

- 상위 요청은 1MB 정렬 블록으로 한다. 메모리에 전체 256MB까지 두고 오래된 것부터 버린다. 받는 중인 블록은 버리지 않는다.
- 같은 블록을 동시에 요청하면 한 번만 받는다(`tokio::sync::OnceCell`). 실패는 캐시하지 않는다(`get_or_try_init`).
- 블록 끝까지 읽히면 다음 블록을 미리 받는다.
- 응답은 한 블록 안으로 잘라 206으로 준다. 파일 전체 길이는 첫 상위 응답의 `Content-Range`에서 얻는다. 마지막 블록은 1MB보다 짧다.
- static1 경로에는 파일 해시(md5)가 들어 있어 같은 주소의 내용이 바뀌지 않는다. 캐시 무효화는 필요 없다.
- Range 없는 요청(이미지)은 통째로 받는다. 단일 Range(`start-`, `start-end`, `-길이`)가 아닌 형식도 RFC 9110대로 Range를 무시하고 통째로 준다.
- **블록 크기는 1MB로 정했다**(research.md 7절 "터널 시작과 static1 속도"). 터널로 1MB 블록은 약 2초, 512KB는 약 1.5초, 256KB도 1~2초라 블록을 줄여도 첫 화면은 크게 빨라지지 않는다. 720p 샘플 1MB는 재생 약 8초 분량이고 받는 속도는 재생의 5~8배라 다음 블록 미리 받기 하나로 따라간다. 샘플은 `moov`가 앞에 있어 첫 블록으로 재생을 시작할 수 있다. 첫 블록을 작게 하거나 동시에 여러 블록을 받는 것은 실제 재생에서 부족할 때 다시 본다.

### 7.3 캐시와 저장

| 대상 | 방식 |
|---|---|
| 이미지·동영상 | `media.rs`가 관리한다. 커스텀 프로토콜 응답에는 웹뷰 HTTP 캐시가 적용되지 않으므로 직접 캐시한다. 먼저 7.2의 메모리 블록 캐시, 이후 디스크 캐시로 넓히고 설정에 용량 한도·비우기를 둔다. |
| API 응답 | 캐시하지 않는다. 즐겨찾기·점수는 항상 최신이어야 한다. |
| 블랙리스트 | 로그인 시와 창이 다시 활성화될 때 갱신하고 설정 파일에 마지막 값을 저장(오프라인으로 시작해도 필터 적용). |
| 자격 증명 | OS 키체인(macOS Keychain, Windows 자격 증명 관리자). 설정 파일·로그·URL에 키를 남기지 않는다. |
| 설정·최근 검색어 | 앱 설정 디렉터리의 JSON 파일 하나. |

처음 계획은 웹뷰 HTTP 캐시에 맡기는 것이었지만, 핫링크 차단 때문에 미디어가 `media://`로 옮겨 오면서 캐시도 앱이 갖게 됐다. 용량 한도를 앱이 정할 수 있게 된 것은 덤이다.

## 8. 디자인

### 방향
e621은 색이 강한 그림이 수천 장 쏟아지는 곳이다. **색은 그림이 갖고, 앱은 물러선다.** 앱이 쓰는 강한 색은 하나의 의미에만 쓴다: **태그 카테고리**(아티스트, 캐릭터, 종 …). e621 사용자가 이미 아는 색-카테고리 대응을 따르되 색값은 새로 조율한다. 검색창에 친 태그도, 뷰어의 태그 목록도 같은 색 체계를 쓰므로 색이 장식이 아니라 정보가 된다.

### 토큰 (시스템 설정을 따라 라이트/다크)
스타일은 **Tailwind CSS v4**로 쓴다. 토큰은 `src/styles/app.css`의 CSS 변수에 두고 `@theme inline`으로 유틸리티(`bg-panel`, `text-dim`, `text-tag-species` …)에 연결한다. Tailwind 기본 색 팔레트와 반경 단계는 지워서 토큰 밖의 값을 쓰지 못하게 한다. 유틸리티로 표현하기 어색한 곳(그리드 배치, 전환 애니메이션)만 컴포넌트 `<style>`을 쓴다.

- 빈 검색 화면은 제목, 사용법 한 줄, 누르면 검색어에 들어가는 예시 태그로 이뤄진다. 예시 태그는 카테고리 색을 써서 첫 화면부터 색 체계를 보여 준다.
- 썸네일은 카드가 아니다. 테두리·그림자·둥근 모서리 없이 틈만 둔다. GIF/동영상/즐겨찾기 여부는 모서리에 작은 기호 하나로만 표시한다.
- macOS는 투명 제목줄(신호등 버튼이 사이드바 위에 얹힘), Windows는 기본 제목줄을 쓴다. Windows 커스텀 제목줄은 스냅 레이아웃 등 OS 동작을 다시 만들어야 해서 쓰지 않는다.

### 움직임
- 사용자가 일으키지 않는 애니메이션은 없다.
- 하나만 공들인다: **썸네일에서 뷰어로 열리고 닫힐 때** 썸네일 자리에서 커지는 전환(View Transitions API). `document.startViewTransition`이 없거나 `prefers-reduced-motion`이면 즉시 전환한다. macOS의 WKWebView는 Safari 18 이상의 WebKit에서 지원하므로 macOS 14 초기 상태처럼 WebKit이 오래된 경우를 대비해 기능 검사를 한다.

### 자기 검토
첫 구현(사이드바와 본문을 탁한 회색 판 두 장으로 나누고 아이콘 없이 글자만 둔 화면)은 와이어프레임처럼 투박하다는 피드백을 받았다. 위계가 없고 재질감이 없어서였다. 그래서 반투명 사이드바, 떠 있는 본문 패널, 아이콘, 검색창 상태 표현을 더했다. 그 전에 처음 떠올린 안은 "거의 검은 배경 + 형광 강조색 하나 + 둥근 카드 그리드"였다. 이미지 뷰어라면 누구나 내놓을 기본값이라 버렸다. 대신 (1) 배경을 순흑이 아닌 차가운 회청색으로 해서 그림의 색이 틀어져 보이지 않게 하고, (2) 강조색을 하나 두는 대신 태그 카테고리 색을 정보로 쓰고, (3) 카드를 없애고 그림 자체가 격자를 이루게 했다.

## 9. 다국어

- **기본 언어는 영어.** 시스템 언어가 한국어면 한국어로 시작한다(`navigator.language`. WKWebView는 번들 지역화와 관계없이 시스템 언어를 돌려준다, research.md 8절). 설정에서 "시스템 / English / 한국어"를 고를 수 있다(1단계 10번).
- 라이브러리 없이 `src/lib/i18n/`에 언어별 사전을 둔다. `en.ts`가 기준이고 `ko.ts`는 같은 타입(`Messages`)을 따라야 하므로 **키가 빠지면 타입 검사에서 실패한다.**
- 화면에서는 `m().nav.search`처럼 객체 경로로 읽는다. 문자열 키를 쓰지 않으므로 오타가 컴파일 단계에서 걸린다.
- 숫자나 값이 들어가는 문구는 문자열 대신 함수로 정의한다. 예: `hidden: (n) => n === 1 ? "1 post hidden" : `${n} posts hidden``.
- 날짜·숫자는 `Intl`에 현재 언어를 넘겨 형식화한다.
- **Rust는 사용자에게 보일 문구를 만들지 않는다.** 오류는 `{ code: "unauthorized" }`처럼 코드와 값만 보내고, 프런트엔드가 언어별 문구로 바꾼다. 연결 실패 코드(6.4절)가 첫 사례다.
- 코드 주석과 개발자용 오류 메시지는 영어로 쓴다(공개 저장소).
- Windows 설치 파일(NSIS)도 영어·한국어를 넣는다. macOS 앱 메뉴는 Tauri 기본 메뉴를 쓰며, 메뉴를 직접 만들게 되면 같은 사전을 쓴다.
- 언어를 더 늘릴 때는 사전 파일 하나를 추가하고 `Locale` 타입에 넣으면 된다.

## 10. 배포

| | macOS | Windows |
|---|---|---|
| 산출물 | `.dmg` (Apple Silicon, macOS 14 이상) | NSIS `-setup.exe` (x64, Windows 10/11) |
| 빌드 위치 | GitHub Actions `macos-latest` (로컬도 가능) | GitHub Actions `windows-latest` |
| 서명 | Developer ID Application + 공증 | 미서명 (첫 실행 시 SmartScreen 경고) |
| 업데이트 | `tauri-plugin-updater` + GitHub Releases `latest.json` | 동일 |

- macOS 최소 버전은 **14**로 둔다. 처음 이유였던 웹뷰 프록시는 없앴다. View Transitions 같은 웹 기능은 macOS 버전이 아니라 WebKit 버전(Safari 18 이상)에 달려 있어 14가 보장하지 않으므로 기능 검사로 쓴다(8절 움직임). 낮출 필요가 생기면 그때 기능별로 확인한다.
- 버전은 `src-tauri/tauri.conf.json` 한곳에서만 관리한다. 태그(`v0.1.0`)를 푸시하면 Actions가 두 플랫폼을 빌드해 GitHub Release 초안을 만든다.
- 업데이트 서명 키(`tauri signer generate`)의 개인 키는 GitHub Secrets에만 둔다. 잃어버리면 기존 설치본에 업데이트를 보낼 수 없으므로 따로 백업한다.
- 공증용 Apple 자격 증명(App Store Connect API 키)도 GitHub Secrets에 둔다.
- **라이선스**: 저장소는 MIT(`LICENSE`). 배포물에는 의존성 라이선스 고지를 함께 넣는다. gotatun은 MPL-2.0이라 소스를 어디서 받는지 알려야 하고, Wanted Sans는 OFL 전문(`src/assets/fonts/WantedSans-OFL.txt`)을 함께 둔다. 고지 파일은 1단계 11번에서 도구(예: cargo-about)로 만든다.
- **배포 시 e621 UA**: 로그인한 사용자 이름을 넣고, 로그인하지 않았으면 개발자 사용자명을 넣는다(`Tailgate/0.1.0 (by Nyabi on e621)`).

## 11. 위험 요소

| 위험 | 대응 |
|---|---|
| 유저스페이스 터널 (gotatun 적합성, smoltcp 처리량) | **macOS에서 검증 완료**: 시스템 VPN 없이 e621 API 200, Cloudflare 10MB 5.2 MB/s(직접 9.4 MB/s, 경로가 도쿄 경유라 동일 조건 아님). Windows에서는 아직. |
| 동영상이 `media://`로 사실상 재생 안 됨 | 원인 확인: WKWebView가 MP4를 수~수십 바이트 Range로 수백 번 읽고, 각각이 도쿄 왕복(약 145ms)이 된다. 블록 캐시로 해결(7.2절). static1 속도가 느리면 블록 크기·동시 받기로 조정. |
| WebView2의 커스텀 프로토콜 동영상 Range 처리 | Windows에서 실측 필요. 주소 형식은 `http://media.localhost/…`. |
| 루프백 SOCKS 포트를 다른 로컬 프로세스가 쓸 수 있음 | 127.0.0.1에만 바인드, 실행마다 임의 포트, 앱 종료 시 닫힘. 웹뷰는 쓰지 않으므로, 필요하면 reqwest 사용자 정의 커넥터로 바꿔 포트 자체를 없앨 수 있다. |
| 터널 시작 지연 (약 3~4초, 대부분 600KB 서버 목록 받기) | 서버 목록을 디스크에 캐시하고 백그라운드에서 갱신한다(1단계 9번). 핸드셰이크 대기는 도쿄 왕복 한두 번이 더해진다. |
| 터널 끊김·실패 시 트래픽 누출 | 킬 스위치(6.3절): 막힌 채 시작, 키체인 오류도 막힘, 핸드셰이크 뒤에만 열림, 실패 시 막힘 유지. 끊긴 연결은 타임아웃으로 끝난다(6.5절). 실행 중 끊김 감지·재연결과 라우트 전환 시 연결 끊기는 1단계 9번. |
| 키체인 접근 거부·잠김 | `credentialStore` 실패로 막힌 채 남는다. 설정 화면에서 다시 시도할 수 있게 한다(1단계 9번). |
| Mullvad API 변경, 기기 수 제한 | Mullvad 코드는 `tunnel/mullvad.rs` 한곳. 기기 수 초과 응답은 "다른 기기를 지우세요" 안내로 처리. |
| macOS WKWebView의 WebM 재생 여부 미확인 | MP4 변형을 먼저 쓴다. MP4 없는 WebM은 실측 후 대체 방법을 정한다. |
| 수천 장 스크롤 시 메모리·DOM 증가 | 보이는 행만 그리는 가상 스크롤. 그리드에서는 동영상을 재생하지 않는다. |
| UA·rate limit 위반으로 차단 | UA와 스로틀은 `api/client.rs` 한곳에서만. 그 밖의 API 호출 경로를 만들지 않는다. |
| legacy 응답 형식 변경 | 필수가 아닌 필드는 `Option`. 픽스처로 디코딩 테스트 고정. |
| 비밀 값 노출 (e621 API 키, WireGuard 개인 키, Mullvad 계정 번호) | OS 키체인에만 저장. 웹뷰로 보내지 않음. 로그·오류 메시지에 넣지 않음(`.conf` 파서 오류도 키 값은 넣지 않는다). |
| 업데이트 서명 키 분실 | 별도 백업. 분실 시 사용자가 수동으로 재설치해야 한다. |

## 12. 단계별 진행

각 항목이 끝나면 확인할 수 있게 알리고, 요청하면 커밋한다. 진행 상황은 status.md.

**1단계**
1. 골격: `git init`, Tauri 2 + Svelte 5 + Vite, 번들 ID, 글꼴 번들, Tailwind 토큰, macOS 투명 제목줄.
2. 터널 개념 검증: `.conf` 파서 → gotatun + smoltcp → SOCKS5 → reqwest. 미디어는 `media://`로 Rust 경유, 동영상 블록 캐시.
3. API 계층: 클라이언트·스로틀·모델, Pawru 픽스처로 디코딩 테스트.
4. 계정: keyring, 로그인 화면, `/users/me`.
5. 검색: 태그 입력·자동완성, 3:4 격자·가상 스크롤·무한 스크롤.
6. 블랙리스트: 테스트 먼저, 그리드 연결.
7. 뷰어: 전환 애니메이션, 줌·패닝, 원본 로드, 동영상, 태그 패널, 키보드.
8. 즐겨찾기·투표·다운로드.
9. 연결 설정 완성: 설정 화면(직접 / .conf / Mullvad 로그인·서버 선택), 서버 목록 캐시, 실행 중 끊김 감지·재연결, 라우트 전환 시 연결 끊기(6.3절 4·5).
10. 설정, 언어 선택, 18세 확인 화면.
11. 배포: GitHub Actions(두 플랫폼), macOS 서명·공증, 업데이터, 라이선스 고지.
