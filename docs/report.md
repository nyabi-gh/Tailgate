# Tailgate 구현 계획

Windows·macOS용 e621 뷰어. 다른 사람에게도 배포한다.

- 이 문서는 **무엇을 어떻게, 왜 그렇게 만드는지**를 적는다. 자주 바뀌지 않는다.
- 어디까지 됐고 다음에 무엇을 하는지는 [status.md](status.md)에만 적는다.
- 근거가 된 조사·실측은 [research.md](research.md)에 있다. 본문의 "research.md N절"은 그 문서를 가리킨다.

## 1. 개요

**Tauri 2(Rust) + Svelte 5(TypeScript) + Tailwind CSS v4 + 앱 내장 WireGuard 터널.**

| 맡는 쪽 | 하는 일 |
|---|---|
| Rust | API 호출·스로틀·인증, 블랙리스트, 다운로드, 터널, 미디어 파일 받기 |
| 웹뷰 | 화면 그리기. Rust가 넘겨준 미디어를 표시·재생한다(GIF·동영상 디코딩은 웹뷰 몫) |

앱의 외부 요청은 모두 Rust에서 나가고, 앱 안의 SOCKS5 프록시와 (설정했다면) 터널을 거친다.

- **API는 Rust에서만 부른다.** 웹뷰가 부르면 브라우저 UA가 나가서 e621 규칙(전용 UA)을 어기고, 스로틀을 우회하는 경로가 생긴다. API 키는 사용자가 로그인 시트에 입력하는 순간에만 웹뷰에 있고, 보낸 뒤 입력값을 지운다. 그 뒤로는 Rust만 갖는다.
- **미디어도 Rust가 받아 `media://`로 넘긴다.** static1은 웹뷰의 cross-site 요청을 핫링크로 보고 403을 준다(research.md 7절). 웹 페이지는 그 헤더를 바꿀 수 없다.

## 3. 기능 범위

### 1단계 (MVP)
- **계정**: 사용자명 + API 키 로그인, `/users/me.json`으로 확인, 로그아웃. 로그인 없이도 둘러보기 가능.
- **검색**: 태그 입력(자동완성, 입력한 태그를 카테고리 색으로 표시), 정렬 메뉴, 최근 검색어(태그 있는 검색만 10개, 빈 검색창에 포커스하면 목록으로 보이고 설정에서 지운다). 태그 없는 검색은 e621의 첫 화면과 같은 최신 게시물이고, 앱은 이 화면으로 열린다. 따로 "홈"을 두지 않는 것은 같은 격자가 두 화면에 생겨 어디에 있는지 헷갈리기 때문이다(2026-10-21 결정). 기간별 인기 목록은 정렬과 다르므로 사이드바 "인기"로 따로 둔다(2단계). 고른 정렬은 기억하지 않는다. 기억하면 첫 화면이 최신순이 아니게 되기 때문이다(2026-10-21 결정).
- **그리드**: 같은 크기의 3:4 세로형 칸에 그림을 꽉 채워(잘라) 넣는 격자, 가상 스크롤, 무한 스크롤, 썸네일 크기 조절(Ctrl/⌘ + 휠 또는 슬라이더, 설정 화면에도 같은 슬라이더. 고른 크기는 다음 실행에도 유지). 처음에는 원본 비율을 지키는 행 정렬(justified)이었으나, 칸마다 폭이 달라 어수선하다는 사용자 의견으로 2026-10-21에 바꿨다. 그림 전체는 뷰어에서 본다.
- **뷰어**: 창 전체를 덮는 뷰어. 이미지는 샘플을 먼저 띄우고 원본은 확대해서 샘플 해상도를 넘거나 "원본 보기"를 누를 때 받음(열 때마다 받으면 넘기기가 느려서). GIF는 샘플이 정지 이미지라 처음부터 원본. 줌·패닝, 동영상(MP4 우선) 반복 재생, 음소거로 시작하고 켜면 실행 동안 기억. 오른쪽 패널에 메타 정보, 출처 링크(기본 브라우저, opener 권한은 http/https 전체), 카테고리별 태그. ←/→, Esc, I(정보), 0(맞춤).
- **키보드**: ←/→ 이전·다음, Esc 닫기, F 즐겨찾기, ↑/↓ 투표, / 검색창, D 다운로드.
- **즐겨찾기·투표**, 내 즐겨찾기 목록.
- **블랙리스트**: 계정의 블랙리스트(로그아웃 상태에서는 e621의 익명 기본 목록)를 사이트와 같은 규칙으로 Rust에서 평가해 걸러 냄(research.md 2절). "N개 숨김"을 누르면 그 검색 동안 보이게 함.
- **다운로드**: 원본을 지정 폴더에 저장. 저장 대화상자 대신 기본 폴더로 바로 저장한다. 폴더는 기본 `~/Downloads/Tailgate`이고 설정에서 대화상자로 고른다. 파일 이름은 규칙으로 정한다(기본 `{id}_{artist}`): 토큰은 `{id}` `{md5}` `{artist}`(사람을 가리키는 첫 화가 태그) `{copyright}` `{character}`(각각 첫 태그) `{rating}`(s/q/e)이고 확장자는 뒤에 붙는다. 값이 없는 토큰은 옆의 구분자(`_` `-` `.` 공백)와 함께 빠진다. 서로 다른 게시물이 같은 이름이 되어 "이미 저장됨"으로 건너뛰지 않게 `{id}`나 `{md5}`가 꼭 있어야 하고, 하위 폴더(`/`, `\`)는 받지 않는다. 태그 값은 60자, 이름은 200바이트에서 자르고, 파일 이름에 쓸 수 없는 문자는 `_`로 바꾼다. 설정 화면은 입력하는 동안 예시 게시물의 이름이나 오류를 보여 준다.
- **연결**: 직접 연결 / WireGuard 설정 파일(.conf 가져오기) / Mullvad 계정(서버 위치 선택). 연결 상태를 사이드바 아래에 표시.
- **설정**: 계정, 연결, 다운로드 폴더와 파일명 규칙, 썸네일 크기, 캐시 비우기, 언어.
- **자동 업데이트**: 다른 사람에게 배포하므로 1단계에 넣는다.
- **18세 이상 확인**: 처음 실행할 때(e621 약관). 확인하기 전에는 앱 화면을 만들지 않아 게시물·썸네일 요청이 나가지 않는다. 연결과 계정 확인(`/users/me`)은 콘텐츠를 보여 주지 않으므로 그대로 진행한다. 답은 설정 파일에 두고, 저장하지 못하면 이번 실행만 통과하고 다음 실행에서 다시 묻는다.

### 2단계
- 태그 클릭으로 재검색, 우클릭 메뉴(검색에 추가/제외/새 탭에서 검색)
- 검색 탭 여러 개(창 상단 탭)
- Pool 목록과 순서대로 읽는 리더
- Set 목록·열람·추가/빼기
- 댓글과 DText 렌더링
- 인기 게시물(일·주·월 기간별. 정렬 메뉴의 점수순은 전체 기간이라 늘 같은 게시물이 위에 온다)

### 3단계 (필요해지면)
- 저장한 검색(사이드바 고정), 댓글 작성, 일괄 다운로드(풀 전체 등, API 스로틀 준수)

## 4. 구조

Tauri 기본 구조에 폴더만 나눈다. Cargo 워크스페이스나 크레이트 분리는 하지 않는다. 빌드가 느려지면 그때 `api`를 크레이트로 뗀다. 파일마다 구현됐는지는 status.md에 적는다.

```
tailgate/
  src-tauri/
    src/
      main.rs            진입점
      lib.rs             Tauri 빌더, 창 생성(플랫폼별 옵션), 상태 조립, 이벤트 연결
      commands.rs        프런트엔드에 노출하는 명령 (얇게: 검증 → 호출 → 반환)
      network.rs         SOCKS 프록시와 터널 소유, 연결 상태(watch)와 실패 코드, e621용 HTTP 클라이언트
      media/
        mod.rs           media:// 프로토콜: static1 data/ 경로만, 앱 연결로 받아 응답, Range 처리
        blocks.rs        동영상 블록 캐시 (1MB 블록, LRU)
        disk.rs          이미지 디스크 캐시 (앱 캐시 디렉터리의 `media/`, 한도, 오래 쓰지 않은 것부터 지움, 비우기)
      secrets.rs         OS 키체인 (keyring-core + 플랫폼 저장소)
      tunnel/
        mod.rs           Tunnel::start(핸드셰이크까지)/stop. 밖에서는 이것만 쓴다
        config.rs        WireGuard .conf 파서 → TunnelConfig
        mullvad.rs       토큰, 기기 등록/삭제, 서버 목록 → TunnelConfig
        wg.rs            gotatun Device에 smoltcp 패킷 큐를 꽂는 IpSend/IpRecv 어댑터
        netstack.rs      smoltcp 인터페이스, async TcpStream, 터널 안 DNS
        socks.rs         127.0.0.1 SOCKS5 서버, Route(Direct/Tunnel/Blocked)
      api/
        mod.rs           Api, ApiError(오류 코드. 프런트엔드에는 코드와 값만 보내고 문구는 프런트엔드 몫)
        client.rs        e621 요청, UA, Basic 인증, 스로틀, 재시도
        models.rs        e621 원본 응답(serde) → 앱 모델 정규화
        endpoints.rs     posts, users/me, autocomplete, 블랙리스트, 즐겨찾기·투표, 내 즐겨찾기 목록, PostSearch(페이지 넘김)
        testing.rs       테스트용 가짜 e621 서버 (테스트 빌드에서만)
      search.rs          화면마다 하나씩 열린 검색(태그 검색, 내 즐겨찾기), 검색어 태그의 카테고리를 결과에서 찾기
      blacklist.rs       파서 + 평가기 (e621ng의 블랙리스트 코드를 옮김)
      account.rs         API 키 저장/삭제(키체인 `e621-account`), 로그인·로그아웃, 시작 시 복원·확인, 401 처리, 계정 상태(watch)
      settings.rs        설정 JSON (앱 설정 디렉터리의 `settings.json`): 연결·일반·보기·다운로드·캐시 칸. 연결 외의 칸은 읽지 못한 파일을 덮어쓰지 않음
      relays.rs          Mullvad 서버 목록 디스크 캐시(앱 캐시 디렉터리의 `relays.json`, ETag), 위치 목록, 서버 고르기
      download.rs        원본 다운로드(`.part`로 받아 이름 바꾸기, 진행률 이벤트), 설정의 폴더(기본 `~/Downloads/Tailgate`)
      download/name.rs   파일 이름 규칙(`{id}_{artist}` 같은 템플릿) 해석·검사·이름 만들기
    examples/
      tunnel_probe.rs    실제 Mullvad 서버로 터널을 검증하는 수동 점검 도구
      api_probe.rs       앱과 같은 경로로 실제 e621 API를 불러 응답 구조를 확인하는 수동 점검 도구
    tests/fixtures/      Pawru 픽스처 재사용 (실제 응답 JSON)
  src/                   Svelte 5 + TypeScript
    lib/
      connection.svelte.ts  연결 상태 (명령 + 이벤트 구독), canLoadRemote(), routeCount(), 연결 설정 명령
      account.svelte.ts  계정 상태 (명령 + 이벤트 구독), signIn/signOut
      media.ts           static1 URL → media:// 주소, 뷰어에 띄울 미디어 선택(viewerMedia)
      platform.ts        OS 판별, 단축키 표기
      i18n/              en.ts(기준), ko.ts, 현재 언어 상태
      views.ts           사이드바 화면 목록
      layout.ts          격자 계산(열 수·칸 크기·보이는 범위), 썸네일 크기 범위 (순수 함수, vitest)
      zoom.ts            뷰어 줌·패닝 계산(맞춤 배율, 커서 기준 확대, 이동 제한) (순수 함수, vitest)
      viewer.svelte.ts   뷰어 상태(열린 게시물, 이전·다음, 정보 패널, 음소거)
      search.svelte.ts   화면별 게시물 목록(PostList: 시작·다음 페이지·다시 시도·블랙리스트 보이기), 알게 된 태그 카테고리, 블랙리스트 변경 이벤트
      blacklistMarks.ts  검색 하나의 숨김 표시. 페이지 응답과 블랙리스트 변경 이벤트를 세대 번호로 순서 맞춤 (순수, vitest)
      settings.svelte.ts 일반·보기 설정(언어, 18세 확인, 칸 폭, 최근 검색어). 화면을 그리기 전에 읽음
      downloadSettings.ts  다운로드 폴더·파일 이름 규칙 명령
      storage.ts         이미지 캐시 사용량·한도·비우기 명령, 크기 표시 (vitest)
      actions.svelte.ts  즐겨찾기·투표(먼저 반영 후 응답으로 맞춤)·다운로드와 진행률
      toast.svelte.ts    화면 아래 알림
      errors.ts          API 오류 코드 → 문구
      posts.ts           Rust 모델의 TS 타입, API 오류 코드
      tags.ts            태그 토큰 해석(제외·메타태그), 카테고리 색
    components/          Sidebar, ConnectionStatus, TagInput, SortMenu, Grid, Thumb, Viewer, MediaStage, InfoPanel, SignInSheet, Settings, MullvadSignInSheet, AgeCheck, Toasts …
    Root.svelte          18세 확인 전에는 AgeCheck, 뒤에는 App (App은 만들어지자마자 게시물을 받으므로)
    styles/app.css       Tailwind 진입점, 디자인 토큰(CSS 변수 + @theme), 기본 스타일
```

원칙:
- **로직은 Rust, 화면은 Svelte.** 블랙리스트, 페이지네이션 커서, 응답 정규화, DText 파싱(2단계)은 Rust에서 하고 `cargo test`로 고정한다. 프런트엔드 테스트는 `layout.ts`처럼 순수 함수만 두고 vitest(`npm test`)로 돌린다.
- Repository 계층, DI 컨테이너, 상태 관리 라이브러리는 쓰지 않는다. 상태는 `lib/*.svelte.ts`의 Svelte runes 모듈 몇 개면 충분하다. 명령 이름과 타입은 그 명령을 쓰는 모듈(`connection`, `account`, `search`, `actions`)에 둔다. 처음 계획한 `ipc.ts`, `state/`, `views/`는 만들지 않았다(화면은 `components/`).
- Rust↔TS 타입은 처음에는 손으로 맞춘다(모델이 10개 안팎). 어긋나는 일이 생기면 `ts-rs`로 생성하는 방식으로 바꾼다.
- Rust 코드는 `cargo fmt`(기본 설정)와 `cargo clippy`를 통과시킨다.

## 5. 데이터 흐름

```
Svelte 화면 → search.svelte.ts → invoke("search_next", {id})
  → commands.rs → PostSearch(검색마다 하나) → api::client
      스로틀(요청 시작 간격 최소 1초. 응답을 기다리는 동안 다음 요청이 막히지는 않는다)
      UA "Tailgate/<버전> (by <user> on e621)", Authorization: Basic …
      401 → 로그아웃 상태 전환 / 429·503 → Retry-After(30초 이하) 또는 1·2·4초 백오프(최대 3회) / 410 → 끝
  → serde 디코딩·정규화 → 블랙리스트 평가 → { posts, blacklisted(id 목록), done }
  → 화면이 <img src="media://localhost/data/…">로 표시 (Windows는 http://media.localhost/data/…)
  → media.rs가 앱 연결(SOCKS → 직접 또는 터널)로 static1에서 받아 응답
```

- **페이지 넘김**: 검색 하나가 Rust의 `PostSearch` 하나다(태그, 다음 페이지, 이미 돌려준 id). 태그에 `order:`가 없으면 `page=b<받은 것 중 가장 작은 id>`, 있으면 `page=N`(750까지). 한 페이지는 100개이고, 그보다 적게 오면 끝이다. 프런트엔드는 검색 id만 들고 있는다. 처음에는 불투명한 커서 문자열을 주고받으려 했지만, 중복 제거에 id 집합이라는 상태가 필요해 Rust가 검색 상태를 갖기로 했다(2026-10-19).
- **블랙리스트는 첫 페이지 전에 받는다**(`/users/me`, 자격 증명마다 한 번). 모르는 채로 게시물을 보내지 않는다. 걸린 게시물도 id와 함께 보내서 "N개 숨김"을 누르면 다시 받지 않고 보인다.
- **한 페이지가 전부 블랙리스트로 숨겨지면** 다음 페이지를 이어 받는다. 한 번에 최대 5페이지(스로틀로 약 5초)까지만 하고, 그 뒤에는 그리드가 스크롤에 맞춰 다시 요청한다.
- **중복 제거**: `PostSearch`가 돌려준 id 집합으로 거른다. 페이지 번호 방식에서 게시물이 다음 페이지로 밀려 다시 오는 경우다.
- **미디어 선택**(`media.ts` 한곳): 썸네일은 `preview`, 칸 폭이 240px 이상이면 `sample`(폭 256px 미리보기가 Retina에서 눈에 띄게 흐려지는 크기. `sample`은 몇 배 크므로 그때만), 뷰어는 `sample` → 원본은 요청/확대 시 `file`. 동영상은 `720p` → `480p` → `variants.mp4` → 원본 WebM 순. URL이 null이면 플레이스홀더.
- **원격 미디어는 연결이 준비된 뒤에만 요청한다.** 준비 전 요청은 킬 스위치에 막혀 실패하고, 웹뷰가 실패를 기억해 다시 요청하지 않는다. 화면은 `connection.svelte.ts`의 `canLoadRemote()`를 보고 렌더링한다.

## 6. 연결 (앱 내부 전용 VPN)

### 6.1 구조

```
            ┌──────────────────── Tailgate 프로세스 ─────────────────────────────────┐
 웹뷰 ──media://──▶ media.rs ─┐                                                     │
            │                 ├─▶ reqwest ─socks5h─▶ socks.rs ─▶ netstack.rs(smoltcp) ─IP─▶ wg.rs ⇄ gotatun Device ─┼─UDP─▶ WireGuard 서버 ─▶ e621
 화면 ─invoke─▶ api(예정) ─────┘                                                     │
            └──────────────────────────────────────────────────────────────────────┘
```

- **권한 상승이 필요 없다.** OS에 VPN 인터페이스를 만들지 않으므로 다른 앱과 시스템 라우팅에 영향이 없다.
- **WireGuard 프로토콜 처리(핸드셰이크·재키잉·keepalive)는 gotatun의 `Device`가 한다.** OS TUN 대신 `with_ip_pair`로 smoltcp와 패킷을 주고받는 어댑터(`wg.rs`)만 우리가 쓴다.
- **웹뷰는 외부로 직접 요청하지 않는다.** 그래서 웹뷰 프록시 설정(`proxy_url`)이 필요 없고, 루프백 SOCKS는 Rust의 HTTP 클라이언트만 쓴다.

### 6.2 연결 방식

설정 화면의 "연결" 칸에서 고른다. 방식(`direct`/`wireGuard`/`mullvad`)과 Mullvad 위치는 `settings.json`에, 비밀 값은 키체인에 둔다. 방식을 바꾸면 저장한 뒤 바로 다시 연결한다.

- **직접 연결**: SOCKS가 그냥 직접 연결한다.
- **WireGuard 설정 파일**: 표준 `.conf`를 가져온다(`PrivateKey`, `Address`, `DNS`, 피어의 `PublicKey`, `PresharedKey`, `Endpoint`, `PersistentKeepalive`). 첫 `[Peer]`만 쓴다. `AllowedIPs`는 앱 트래픽 전체를 보내므로 무시한다. 터널 안 DNS가 꼭 필요하므로 `DNS`가 없는 설정은 거절한다. 파일 대화상자는 Rust가 열고(`tauri-plugin-dialog`) 파일도 Rust가 읽어 키체인 `wireguard-config`에 원문 그대로 저장한다. 개인 키가 웹뷰를 거치지 않는다. 설정 파일에는 파일 이름과 서버 주소만 적는다. 같은 파일을 다른 WireGuard 앱에서 동시에 쓰면 서로 끊으므로(6.6절) 설정 화면에 안내한다.
- **Mullvad**: 계정 번호 → 토큰 → 앱이 키 쌍을 만들어 기기로 등록 → 받은 터널 주소와 서버 목록으로 설정을 만든다. 계정 번호는 로그인 시트에서 한 번 보내고 지우며, 화면에는 기기 이름과 만료일만 돌아온다. 서버는 도시로 고르고 그 도시의 활성 서버 중 하나를 무작위로 쓴다(Mullvad 앱과 같음). 핸드셰이크에 답하지 않은 서버는 앱이 켜져 있는 동안 후보에서 빼고(도시의 서버가 모두 빠졌으면 전부 다시 후보), 다른 서버가 남아 있으면 그 자리에서 한 번 더 시도한 뒤에야 실패를 알린다. Mullvad가 활성으로 올려 둔 서버가 계속 답하지 않는 일이 있어서다(research.md 7절). 로그인할 때 남아 있던 기기가 있으면 먼저 지운다. 로그아웃은 계정에서 기기를 지운 다음 키체인 항목을 지우고, 기기 삭제가 실패하면 아무것도 바꾸지 않는다(기기 칸이 쓸 수 없는 키로 남지 않게). 로그아웃해도 방식은 Mullvad로 남아 연결이 막힌다. 직접 연결로 저절로 넘어가지 않는다.
- **첫 실행**(`settings.json`에 연결 설정이 없을 때): 키체인에 Mullvad 기기가 있으면 Mullvad `jp-tyo`, 없다고 확인되면 직접 연결. 설정 파일을 읽지 못했거나 손상됐으면 첫 실행이 아니라 실패(`settings`)다.
- **서버 목록 캐시**: 받은 목록은 필요한 필드만 추려 ETag와 함께 `relays.json`에 둔다. 연결할 때 메모리나 디스크 사본이 있으면 바로 쓰고, 연결된 뒤 `If-None-Match`로 새로 받는다(바뀌지 않았으면 304). 사본으로 고른 서버가 핸드셰이크에 실패하거나 위치에 서버가 없으면 목록을 새로 받아 한 번 더 시도한다. 사본이 깨졌으면 무시하고 받는다(경로를 정하는 값이 아니므로 킬 스위치와 무관).

### 6.3 킬 스위치

트래픽이 의도하지 않은 경로로 나가지 않게 하는 규칙이다. 1·3은 `network.rs`의 테스트로 고정한다(목 키체인으로 오류를 넣고, 로컬 서버에 요청이 닿는지 본다).

1. **프록시는 막힌 채(`Blocked`)로 시작한다.** 저장된 설정을 읽어 직접 연결이라고 확인된 경우에만 `Direct`로 연다. 설정 파일이나 키체인을 읽지 못했거나(접근 거부, 잠김) 저장 값이 깨졌으면 막힌 채로 두고 `failed`를 알린다. 오류를 "설정 없음"으로 취급하지 않는다.
2. **터널은 WireGuard 핸드셰이크가 끝난 뒤에만 연다.** gotatun 장치를 만드는 것만으로는 서버에 닿는다는 보장이 없다(research.md 8절). 핸드셰이크가 끝나야 라우트를 `Tunnel`로 바꾸고 `tunnel` 상태를 알린다.
3. **실패하면 `Blocked`로 남는다.** 터널 모드에서 직접 연결로 넘어가는 코드 경로는 없다.
4. **라우트를 바꾸면 그 전 라우트의 연결을 모두 끊는다.** 라우트는 SOCKS 연결을 맺을 때 정해지므로, 그대로 두면 reqwest가 풀에 둔 연결을 계속 써서 옛 경로로 트래픽이 나간다. `SocksServer`는 라우트를 `watch`로 갖고, 중계 중이거나 아직 연결 중인 요청은 라우트가 바뀌면 바로 닫는다. 바꾸는 순서는 `Blocked`(옛 연결 끊김) → 옛 터널 정지 → 새 경로 → 새 라우트라서 두 경로가 함께 열리는 순간이 없다.
5. **실행 중 끊김을 감지하면 `Blocked`로 바꾸고 `failed {connectionLost}`를 알린 뒤 다시 연결한다.** 5초마다 피어의 `last_handshake`를 보고, 120초(재키잉 주기)가 넘었으면 직접 핸드셰이크를 걸어 20초 안에 끝나지 않으면 끊긴 것으로 본다. gotatun은 데이터를 보낼 때만 재키잉해서, 쉬는 터널은 핸드셰이크 시각만으로 판단할 수 없기 때문이다(research.md 8절). `Device::wait()`가 치명적 오류를 알려도 끊긴 것이다. 진행 중인 요청은 그보다 먼저 smoltcp의 45초 무응답 제한이 끊는다.
6. **다시 연결.** `Network::run` 한 작업이 연결을 맡는다. 일시적인 실패(`relayList`, `tunnel`, `handshake`, `connectionLost`)는 1·2·4…초, 최대 60초 간격으로 계속 다시 시도한다. 키체인·설정 손상·로그인 필요처럼 다시 해도 같은 실패는 사용자가 무언가 바꿀 때(설정 변경, "다시 연결")까지 기다린다. 시도하는 동안은 `connecting`, 실패하면 다음 시도까지 `failed`다.

### 6.4 연결 상태

| 상태 | 뜻 | 원격 요청 |
|---|---|---|
| `connecting` | 시작 직후. 저장된 설정을 읽거나 터널을 세우는 중 | 막힘 |
| `direct` | 직접 연결 | 허용 |
| `tunnel {relay}` | 핸드셰이크까지 끝난 터널. `relay`는 서버 호스트 이름 | 허용 |
| `failed {code}` | 실패. 막힌 채로 남는다 | 막힘 |

- Rust가 `watch` 채널로 갖고, 바뀌면 `connection-changed` 이벤트를 보낸다.
- 화면은 이벤트를 먼저 구독한 뒤 `connection_status` 명령으로 첫 값을 읽는다. 이벤트와 명령 응답은 서로 다른 경로로 와서 순서가 보장되지 않으므로, 응답보다 이벤트가 먼저 왔으면 응답을 버린다.

실패 코드. 화면이 언어별 문구로 바꾼다(9절). 자세한 원인은 Rust 로그에만 남긴다.

| 코드 | 원인 |
|---|---|
| `credentialStore` | 키체인을 읽지 못함(접근 거부, 잠김) |
| `settings` | 설정 파일을 읽지 못함, 손상됨 |
| `savedDevice` | 저장된 Mullvad 기기 정보가 깨짐 |
| `noWireGuardConfig` | WireGuard 방식인데 가져온 파일이 없음 |
| `savedConfig` | 저장된 WireGuard 설정이 깨짐 |
| `mullvadSignedOut` | Mullvad 방식인데 로그인하지 않음 |
| `relayList` | Mullvad 서버 목록을 받지 못함 |
| `noRelay` | 고른 위치에 활성 서버가 없음 |
| `tunnel` | 터널을 세우지 못함(서버 주소, 키, UDP 소켓) |
| `handshake` | 서버가 핸드셰이크에 답하지 않음 |
| `connectionLost` | 실행 중 터널이 끊김 |

연결 설정 명령(로그인, 가져오기, 위치)의 실패는 따로 `SettingsChangeError` 코드로 보낸다: `settings`, `credentialStore`, `network`, `invalidAccount`, `tooManyDevices`, `mullvad`, `unreadableFile`, `invalidConfig {key, missing}`, `unknownLocation`.

- 라우트가 다시 열릴 때마다 화면의 `routeCount()`가 늘고, 그 사이 실패했거나 끊긴 썸네일과 뷰어 미디어를 다시 요청한다.

### 6.5 타임아웃

연결이 죽었을 때 요청이 끝없이 기다리지 않고 오류로 끝나게 한다.

| 대상 | 값 | 비고 |
|---|---|---|
| WireGuard 핸드셰이크 | 10초 | gotatun은 5초(+지터)마다 다시 시도한다. 한 번 더 시도할 여유를 둔다 |
| 터널 안 DNS | 10초 | |
| 터널 안 TCP 연결 | 15초 | |
| 터널 안 TCP 무응답 | keep-alive 15초, 상대 패킷이 45초 없으면 끊음 | smoltcp는 keep-alive만으로는 연결을 끊지 않는다(research.md 8절) |
| e621 HTTP | 연결 30초, 읽기 간격 30초 | 연결 값은 터널 안 DNS + TCP 연결 한도(25초)보다 길게 둔다. 전체 시간 제한은 큰 원본 다운로드를 끊으므로 두지 않는다 |
| Mullvad API | 요청 전체 30초 | 약 600KB인 서버 목록 포함 |

### 6.6 그 밖의 규칙

- **DNS도 터널 안에서 푼다.** SOCKS5에 도메인 이름째로 넘기고(`socks5h`), 설정의 `DNS`(Mullvad는 `10.64.0.1`)로 smoltcp DNS 소켓이 조회한다.
- **Mullvad API 호출은 직접 연결로 한다.** 터널을 세우기 위한 호출이기 때문이다.
- **비밀 값**: WireGuard 개인 키(Mullvad 기기 정보 JSON 안, 가져온 `.conf` 원문)와 Mullvad 계정 번호는 OS 키체인에 저장한다. 서비스 이름은 `pro.tb.nyabi.Tailgate`, 항목은 `mullvad-account`, `mullvad-device`, `wireguard-config`. 키체인 읽기는 macOS 접근 허용 창을 기다릴 수 있으므로 메인 스레드가 아닌 블로킹 작업 스레드에서 한다. 그동안 창은 `connecting`으로 뜬다.
- **smoltcp 난수 시드는 실행마다 OS 난수로 채운다.** TCP 초기 순서 번호와 DNS 질의 ID가 이 시드에서 나오는데, 기본값 0이면 실행할 때마다 같은 값이 반복된다(research.md 8절).
- 터널은 IPv4만 다룬다(smoltcp 인터페이스, DNS A 레코드).
- **같은 WireGuard 키는 한 곳에서만 쓴다.** 서버는 피어 하나에 대해 마지막으로 핸드셰이크한 세션의 키로만 응답을 암호화한다. 같은 키로 터널이 둘이면 먼저 연결한 쪽은 요청은 보내도 응답을 풀지 못하고, 터널 안 DNS가 10초 뒤 실패한다(research.md 7절). 그래서 앱은 한 번에 하나만 실행된다(`tauri-plugin-single-instance`. 두 번째 실행은 터널을 열기 전에 끝나고 떠 있는 창을 앞으로 가져온다). 한 앱 안의 재연결은 옛 터널을 멈춘 뒤 새 터널을 열므로 겹치지 않는다.

## 7. 미디어와 캐시

### 7.1 `media://`

- static1의 `data/` 경로만 받는다. 다른 경로와 `..`, 퍼센트 인코딩은 404로 거절해 임의 URL 요청 통로가 되지 않게 한다.
- 주소: macOS `media://localhost/data/…`, Windows `http://media.localhost/data/…` (`media.ts`가 만든다).
- 받은 상태 코드와 `Content-Type`, `Content-Range`, `Accept-Ranges`를 그대로 넘긴다. `Content-Length`는 wry가 붙인다(macOS에서 확인).

### 7.2 동영상 블록 캐시

WKWebView는 커스텀 프로토콜의 MP4를 8~24바이트짜리 Range로 수백 번 읽는다(research.md 7절). 요청마다 static1로 왕복하면 재생이 시작되지 않으므로, 블록 단위로 받아 두고 작은 Range는 캐시에서 응답한다.

- 상위 요청은 1MB 정렬 블록으로 한다. 메모리에 전체 256MB까지 두고 오래된 것부터 버린다. 받는 중인 블록은 버리지 않는다.
- 같은 블록을 동시에 요청하면 한 번만 받는다(`tokio::sync::OnceCell`). 실패는 캐시하지 않는다(`get_or_try_init`).
- 블록 끝까지 읽히면 다음 블록을 미리 받는다.
- 응답은 한 블록 안으로 잘라 206으로 준다. 파일 전체 길이는 첫 상위 응답의 `Content-Range`에서 얻는다. 마지막 블록은 1MB보다 짧다.
- static1 경로에는 파일 해시(md5)가 들어 있어 같은 주소의 내용이 바뀌지 않는다. 캐시 무효화는 필요 없다.
- Range 없는 요청(이미지)은 통째로 받는다. 단일 Range(`start-`, `start-end`, `-길이`)가 아닌 형식도 RFC 9110대로 Range를 무시하고 통째로 준다.
- **블록 크기는 1MB로 정했다**(research.md 7절 "터널 시작과 static1 속도"). 터널로 1MB 블록은 약 2초, 512KB는 약 1.5초, 256KB도 1~2초라 블록을 줄여도 첫 화면은 크게 빨라지지 않는다. 720p 샘플 1MB는 재생 약 8초 분량이고 받는 속도는 재생의 5~8배라 다음 블록 미리 받기 하나로 따라간다. 샘플은 `moov`가 앞에 있어 첫 블록으로 재생을 시작할 수 있다. 첫 블록을 작게 하거나 동시에 여러 블록을 받는 것은 실제 재생에서 부족할 때 다시 본다.

### 7.3 캐시와 저장

| 대상 | 방식 |
|---|---|
| 이미지·동영상 | `media/`가 관리한다. 동영상은 7.2의 메모리 블록 캐시. 이미지(jpg·png·gif·webp, Range 없는 요청)는 앱 캐시 폴더의 `media/`에 static1 경로 그대로 디스크에 둔다(`media/disk.rs`). WKWebView가 한 실행 안에서는 받은 이미지를 다시 요청하지 않으므로(research.md 7절) 디스크 캐시는 다시 실행한 뒤를 위한 것이다. 파일은 `.part`로 쓴 뒤 이름을 바꾸고, 수정 시각을 마지막 사용으로 삼아 꺼낼 때마다 갱신한다. 최대 크기(기본 1GB, 설정에서 256MB~5GB)를 넘으면 오래 쓰지 않은 것부터 지워 90%까지 줄인다. 사용량은 시작할 때 백그라운드에서 한 번 세고, 그때 남은 `.part`도 지운다. 설정의 [비우기]는 `media/`를 통째로 지운다. 쓰기 실패는 다음 실행이 다시 받으면 되므로 로그만 남긴다. |
| API 응답 | 캐시하지 않는다. 즐겨찾기·점수는 항상 최신이어야 한다. |
| 블랙리스트 | 자격 증명마다 받고, 창이 다시 활성화될 때(최소 5분 간격) 다시 받는다. 바뀌었으면 열린 검색이 이미 받은 게시물도 다시 판정해 화면에 알린다(`blacklist-changed`). 페이지 응답과 이 이벤트는 도착 순서가 보장되지 않으므로 블랙리스트 세대 번호로 어느 판정이 새 것인지 가린다. 설정 파일에는 저장하지 않는다. 저장해 두어도 시작할 때 아끼는 것은 `/users/me` 한 번(약 0.4초)이고, 게시물은 어차피 연결된 뒤에 온다(2026-10-21 결정). |
| 자격 증명 | OS 키체인(macOS Keychain, Windows 자격 증명 관리자). 설정 파일·로그·URL에 키를 남기지 않는다. |
| 설정·최근 검색어 | 앱 설정 디렉터리의 JSON 파일 하나(`settings.json`). 칸은 연결·일반(언어, 18세 확인)·보기(칸 폭, 최근 검색어)·다운로드(폴더, 파일 이름 규칙. 값이 없으면 앱의 기본값을 따름)·캐시(최대 크기)다. 연결 외의 칸을 저장할 때는 읽지 못한 파일을 덮어쓰지 않는다. 덮어쓰면 안의 연결 설정이 사라져 다음 시도부터 첫 실행 규칙이 적용되고, 막혀 있던 연결이 열릴 수 있다(6.3절 1). 화면은 일반 칸을 먼저 읽고 나서 그린다. |

처음 계획은 웹뷰 HTTP 캐시에 맡기는 것이었지만, 핫링크 차단 때문에 미디어가 `media://`로 옮겨 오면서 캐시도 앱이 갖게 됐다. 용량 한도를 앱이 정할 수 있게 된 것은 덤이다.

## 8. 디자인

### 방향
e621은 색이 강한 그림이 수천 장 쏟아지는 곳이다. **색은 그림이 갖고, 앱은 물러선다.** 앱이 쓰는 강한 색은 하나의 의미에만 쓴다: **태그 카테고리**(아티스트, 캐릭터, 종 …). e621 사용자가 이미 아는 색-카테고리 대응을 따르되 색값은 새로 조율한다. 검색창에 친 태그도, 뷰어의 태그 목록도 같은 색 체계를 쓰므로 색이 장식이 아니라 정보가 된다.

### 토큰 (시스템 설정을 따라 라이트/다크)
스타일은 **Tailwind CSS v4**로 쓴다. 토큰은 `src/styles/app.css`의 CSS 변수에 두고 `@theme inline`으로 유틸리티(`bg-panel`, `text-dim`, `text-tag-species` …)에 연결한다. Tailwind 기본 색 팔레트와 반경 단계는 지워서 토큰 밖의 값을 쓰지 못하게 한다. 유틸리티로 표현하기 어색한 곳(그리드 배치, 전환 애니메이션)만 컴포넌트 `<style>`을 쓴다.

- **Wanted Sans Variable** 하나만 쓴다(OFL, 한글·라틴 모두 포함, 앱에 번들). 숫자는 tabular-nums로 점수·ID 열을 맞춘다.
- 크기: 12 / 13 / 15 / 19 / 26px. 데스크톱 앱이라 본문 13px. 굵기는 400·520·650 세 단계.

- 모든 텍스트는 왼쪽 정렬. 사이드바 폭 220px, 뷰어 정보 패널 300px(접을 수 있음).
- **본문은 창 안에 떠 있는 패널**(바깥 여백 8px, 반경 14px, 얇은 테두리 그림자)이고, 사이드바는 그 뒤의 창 바탕에 놓인다.
- **macOS**: 창을 투명하게 하고 사이드바 자리에 시스템 `sidebar` 재질(vibrancy)을 깐다(`lib.rs`의 `build_main_window`). 신호등 버튼은 검색창과 같은 높이에 맞춘다(`x 20, y 33`).
- **Windows**: 지금은 불투명한 `window` 색. Windows 11 Mica는 실기기에서 확인한 뒤 넣는다.
- 아이콘은 Lucide(16px, 선 굵기 1.75). 선택된 항목은 바탕을 채우고 아이콘만 focus 색으로 바꾼다.
- 검색창은 아이콘과 단축키 표시를 갖는다. macOS는 ⌘K, Windows는 Ctrl K, 그리고 입력 중이 아닐 때 `/`로 어디서든 검색창으로 간다. 단축키는 물리 키(`KeyK`)로 판별해 Caps Lock이나 한글 입력 상태와 관계없이 동작한다. macOS의 Ctrl K는 입력창의 "줄 끝까지 지우기"이므로 가로채지 않는다.
- **설정 화면**: 본문 패널 안의 화면(모달 아님), 폭 최대 600px, 왼쪽 정렬. macOS 시스템 설정처럼 섹션 제목 아래 묶인 목록(반경 `md`, `raised` 바탕, 얇은 구분선)으로, 행은 왼쪽 이름·값, 오른쪽 끝 작은 버튼이다. "계정" 칸(e621 로그인·로그아웃)과 "연결" 칸(상태와 "다시 연결", 방식 분할 버튼, 방식별 행: 파일·서버 / 계정·기기·만료·위치)이 있다. 위치는 정렬 메뉴와 같은 기본 `<select>`에 국가별 묶음으로 두고, 국가 이름은 시스템 언어(`Intl.DisplayNames`)로, 도시는 Mullvad 이름 그대로 보인다.
- **연결 표시**(사이드바 아래, 누르면 설정): 직접 연결은 회색 점, 연결 중은 빈 점, 터널은 focus 색 점과 서버 이름(`VPN · jp-tyo-wg-001`), 실패는 경고 아이콘과 "VPN 연결 안 됨". 실패 원인은 마우스를 올리면 보인다. 애니메이션은 쓰지 않는다.
- 검색 화면은 태그가 없으면 최신 게시물 격자다. 처음에는 제목·사용법·카테고리 색 예시 태그로 된 빈 화면이었으나, 열자마자 볼 것이 없어 2026-10-21에 없앴다. 카테고리 색은 검색어 칩과 정보 패널에서 드러난다.
- 썸네일은 카드가 아니다. 테두리·그림자·둥근 모서리 없이 틈만 둔다. GIF/동영상/즐겨찾기 여부는 모서리에 작은 기호 하나로만 표시한다.
- macOS는 투명 제목줄(신호등 버튼이 사이드바 위에 얹힘), Windows는 기본 제목줄을 쓴다. Windows 커스텀 제목줄은 스냅 레이아웃 등 OS 동작을 다시 만들어야 해서 쓰지 않는다.

### 움직임
- 사용자가 일으키지 않는 애니메이션은 없다.
- 하나만 공들인다: **썸네일에서 뷰어로 열리고 닫힐 때** 썸네일 자리에서 커지는 전환(View Transitions API). `document.startViewTransition`이 없거나 `prefers-reduced-motion`이면 즉시 전환한다. macOS의 WKWebView는 Safari 18 이상의 WebKit에서 지원하므로 macOS 14 초기 상태처럼 WebKit이 오래된 경우를 대비해 기능 검사를 한다.

### 자기 검토
첫 구현(사이드바와 본문을 탁한 회색 판 두 장으로 나누고 아이콘 없이 글자만 둔 화면)은 와이어프레임처럼 투박하다는 피드백을 받았다. 위계가 없고 재질감이 없어서였다. 그래서 반투명 사이드바, 떠 있는 본문 패널, 아이콘, 검색창 상태 표현을 더했다. 그 전에 처음 떠올린 안은 "거의 검은 배경 + 형광 강조색 하나 + 둥근 카드 그리드"였다. 이미지 뷰어라면 누구나 내놓을 기본값이라 버렸다. 대신 (1) 배경을 순흑이 아닌 차가운 회청색으로 해서 그림의 색이 틀어져 보이지 않게 하고, (2) 강조색을 하나 두는 대신 태그 카테고리 색을 정보로 쓰고, (3) 카드를 없애고 그림 자체가 격자를 이루게 했다.

## 9. 다국어

- **기본 언어는 영어.** 시스템 언어가 한국어면 한국어로 시작한다(`navigator.language`. WKWebView는 번들 지역화와 관계없이 시스템 언어를 돌려준다, research.md 8절). 설정의 "일반" 칸에서 "시스템 / English / 한국어"를 고르고, 고른 값은 `settings.json`의 `general.language`에 둔다. 화면을 그리기 전에 읽으므로 시작할 때 언어가 바뀌며 깜빡이지 않는다. 언어 이름(English, 한국어)은 그 언어로 쓴다.
- 라이브러리 없이 `src/lib/i18n/`에 언어별 사전을 둔다. `en.ts`가 기준이고 `ko.ts`는 같은 타입(`Messages`)을 따라야 하므로 **키가 빠지면 타입 검사에서 실패한다.**
- 화면에서는 `m().nav.search`처럼 객체 경로로 읽는다. 문자열 키를 쓰지 않으므로 오타가 컴파일 단계에서 걸린다.
- 숫자나 값이 들어가는 문구는 문자열 대신 함수로 정의한다. 예: `hidden: (n) => n === 1 ? "1 post hidden" : `${n} posts hidden``.
- 날짜·숫자는 `Intl`에 현재 언어를 넘겨 형식화한다.
- **Rust는 사용자에게 보일 문구를 만들지 않는다.** 오류는 `{ code: "unauthorized" }`처럼 코드와 값만 보내고, 프런트엔드가 언어별 문구로 바꾼다. 연결 실패 코드(6.4절)가 첫 사례다.
- 코드 주석과 개발자용 오류 메시지는 영어로 쓴다(공개 저장소).
- Windows 설치 파일(NSIS)도 영어·한국어를 넣는다. macOS 앱 메뉴는 Tauri 기본 메뉴를 쓰며, 메뉴를 직접 만들게 되면 같은 사전을 쓴다.
- 언어를 더 늘릴 때는 사전 파일 하나를 추가하고 `Locale` 타입에 넣으면 된다.

## 10. 배포

| | macOS | Windows |
|---|---|---|
| 산출물 | `.dmg` (Apple Silicon, macOS 14 이상) | NSIS `-setup.exe` (x64, Windows 10/11) |
| 빌드 위치 | GitHub Actions `macos-latest` (로컬도 가능) | GitHub Actions `windows-latest` |
| 서명 | Developer ID Application + 공증 | 미서명 (첫 실행 시 SmartScreen 경고) |
| 업데이트 | `tauri-plugin-updater` + GitHub Releases `latest.json` | 동일 |

- macOS 최소 버전은 **14**로 둔다. 처음 이유였던 웹뷰 프록시는 없앴다. View Transitions 같은 웹 기능은 macOS 버전이 아니라 WebKit 버전(Safari 18 이상)에 달려 있어 14가 보장하지 않으므로 기능 검사로 쓴다(8절 움직임). 낮출 필요가 생기면 그때 기능별로 확인한다.
- 버전은 `src-tauri/Cargo.toml` 한곳에서만 관리한다. e621 UA가 컴파일 때 `CARGO_PKG_VERSION`을 읽고, `tauri.conf.json`에 `version`이 없으면 Tauri도 이 값을 쓴다. 그래서 `tauri.conf.json`과 `package.json`에는 버전을 두지 않는다(2026-10-21 결정). 릴리스는 주석 태그(`git tag -a v0.1.0`)를 푸시해 만든다. 태그 메시지가 릴리스 노트이자 앱 업데이트 시트의 노트다.
- main에 푸시하거나 PR을 열면 `.github/workflows/ci.yml`이 macOS·Windows에서 검사(`npm test`·`check`·`build`, `cargo fmt`·`clippy`·`test`)를 돌린다. Rust는 로컬과 같은 버전으로 고정해 새 clippy 규칙이 먼저 CI를 깨지 않게 한다. 액션은 커밋 SHA로 고정한다.
- Windows 산출물은 실제 Windows에서 터널·키체인·`media://`를 확인할 때까지 공개 릴리스에 올리지 않는다(2026-10-21 결정). CI에서는 처음부터 빌드·검사한다.
- **배포 워크플로**(`.github/workflows/release.yml`): `v*` 태그를 푸시하면 `ci.yml`의 검사를 먼저 돌리고, macOS에서 태그와 `Cargo.toml` 버전을 대조한 뒤 빌드·서명·`.app` 공증(Tauri), DMG 공증·staple, 서명 검사(`codesign`, `spctl`, `stapler`), `latest.json` 작성, GitHub Release **초안** 생성까지 한다. 공개는 사용자가 초안을 확인하고 누른다. Tauri는 DMG를 서명만 하고 공증하지 않아서, 산출물을 바로 올리는 tauri-action 대신 이 순서를 직접 쓴다(쓰기 권한을 가진 외부 액션도 하나 줄어든다). 업데이트 산출물(`createUpdaterArtifacts`)은 CI에서만 `--config`로 켜서 로컬 빌드에 서명 키가 필요 없게 한다. Windows는 같은 태그에서 NSIS를 빌드해 워크플로 산출물로만 남긴다.
- 비밀 값은 GitHub 환경 `release`의 시크릿으로 두어 macOS 배포 작업만 읽게 한다: `APPLE_CERTIFICATE`(Developer ID Application `.p12`의 base64), `APPLE_CERTIFICATE_PASSWORD`, `APPLE_API_KEY`(App Store Connect 키 ID), `APPLE_API_ISSUER`, `APPLE_API_KEY_P8`(`.p8` 내용), `TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. 업데이트 서명 개인 키(2026-10-22 생성, 키 ID `8DFE5606731E91CB`, 암호 있음)는 잃어버리면 기존 설치본에 업데이트를 보낼 수 없으므로 사용자가 따로 백업한다.
- **업데이트 경로**: 업데이트 확인·받기도 앱 SOCKS(`socks5h://`)를 거친다. 그래서 킬 스위치가 그대로 적용된다(막힘이면 나가지 않고, Mullvad면 터널로). `tauri-plugin-updater`의 시스템 프록시 기능은 끈다. 확인·받기·설치는 Rust 명령으로 만들고 JS 플러그인 API는 쓰지 않는다. 프록시와 시간 제한을 Rust가 정하고 웹뷰 권한도 늘지 않는다. 주소는 `https://github.com/nyabi-gh/Tailgate/releases/latest/download/latest.json`이고, 초안과 사전 릴리스는 이 주소에 잡히지 않는다.
- **업데이트 화면**: 연결이 처음 열린 뒤 실행마다 한 번 확인한다("자동으로 확인", 기본 켬). 설정 맨 아래에 정보 칸을 두고 버전, [업데이트 확인], 자동 확인, 오픈 소스 라이선스, GitHub 링크를 넣는다. 새 버전이 있으면 시트에 버전과 릴리스 노트를 보여 주고 [업데이트] / [나중에]를 묻는다. 진행률을 보여 준 뒤 macOS는 [다시 시작]으로 다시 켜고, Windows는 NSIS `passive` 설치가 앱을 닫고 진행한다. 시트의 [나중에]는 이번 실행에서 다시 묻지 않고, 정보 칸의 [업데이트…]로 다시 연다. 18세 확인 전에는 앱 화면이 없으므로 확인도 하지 않는다.
- **macOS 서명**: hardened runtime(Tauri 기본값)을 쓰고 엔타이틀먼트는 두지 않는다(샌드박스를 쓰지 않고 키체인은 `keychain` 방식). 공증은 App Store Connect API 키로 하고, CI에서는 임시 키체인에 인증서를 넣는다. 서명한 앱은 개발 빌드가 만든 키체인 항목을 읽을 때 허용 창을 한 번 띄운다.
- **라이선스**: 저장소는 MIT(`LICENSE`). 배포물에는 의존성 라이선스 고지 `THIRD-PARTY-NOTICES.html`을 함께 넣는다. Rust 쪽은 cargo-about으로 두 플랫폼 타깃을 합쳐 만들고, JS 쪽은 번들에 들어가는 패키지만 스크립트로 모은다. 여기에 Tailgate MIT와 Wanted Sans OFL 전문(`src/assets/fonts/WantedSans-OFL.txt`)을 더한다. gotatun 등 MPL-2.0 크레이트는 소스를 어디서 받는지 적는다. 이 파일은 `npm run notices`(`scripts/notices.mjs`)로 만들어 `src-tauri/resources/`에 커밋하고(바뀐 내용을 리뷰할 수 있게), CI가 최신인지 확인한다. 웹 쪽은 Vite 빌드 결과의 모듈 목록으로 실제로 들어간 패키지만 고르고, CSS로 들어가는 Tailwind는 따로 더한다. cargo-about이 찾지 못하는 이름의 라이선스 파일(`LICENSE_MIT`, `license-mit`)은 스크립트가 크레이트 폴더에서 찾아 넣고, 파일이 아예 없는 크레이트는 표준 본문에 그렇다는 설명을 붙인다. 앱에서는 정보 칸의 버튼이 번들 리소스를 기본 브라우저로 연다.
- **배포 시 e621 UA**: 로그인한 사용자 이름을 넣고, 로그인하지 않았으면 개발자 사용자명을 넣는다(`Tailgate/0.1.0 (by Nyabi on e621)`).

| 키체인 접근 거부·잠김 | `credentialStore` 실패로 막힌 채 남는다. 설정 화면의 "다시 연결"이 키체인을 다시 읽는다. |
| Mullvad API 변경, 기기 수 제한 | Mullvad 코드는 `tunnel/mullvad.rs` 한곳. 기기 수 초과 응답은 "다른 기기를 지우세요" 안내로 처리. |
| macOS WKWebView의 WebM 재생 여부 미확인 | MP4 변형을 먼저 쓴다. MP4 없는 WebM은 실측 후 대체 방법을 정한다. |

| legacy 응답 형식 변경 | 필수가 아닌 필드는 `Option`. 픽스처로 디코딩 테스트 고정. |
| 비밀 값 노출 (e621 API 키, WireGuard 개인 키, Mullvad 계정 번호) | OS 키체인에만 저장. 웹뷰로 보내지 않음. 로그·오류 메시지에 넣지 않음(`.conf` 파서 오류도 키 값은 넣지 않는다). |
| 업데이트 서명 키 분실 | 별도 백업. 분실 시 사용자가 수동으로 재설치해야 한다. |

## 12. 단계별 진행

각 항목이 끝나면 확인할 수 있게 알리고, 요청하면 커밋한다. 진행 상황은 status.md.

**1단계**
1. 골격: `git init`, Tauri 2 + Svelte 5 + Vite, 번들 ID, 글꼴 번들, Tailwind 토큰, macOS 투명 제목줄.
2. 터널 개념 검증: `.conf` 파서 → gotatun + smoltcp → SOCKS5 → reqwest. 미디어는 `media://`로 Rust 경유, 동영상 블록 캐시.
3. API 계층: 클라이언트·스로틀·모델, Pawru 픽스처로 디코딩 테스트.
4. 계정: keyring, 로그인 화면, `/users/me`.
5. 검색: 태그 입력·자동완성, 3:4 격자·가상 스크롤·무한 스크롤.
6. 블랙리스트: 테스트 먼저, 그리드 연결.
7. 뷰어: 전환 애니메이션, 줌·패닝, 원본 로드, 동영상, 태그 패널, 키보드.
8. 즐겨찾기·투표·다운로드.
9. 연결 설정 완성: 설정 화면(직접 / .conf / Mullvad 로그인·서버 선택), 서버 목록 캐시, 실행 중 끊김 감지·재연결, 라우트 전환 시 연결 끊기(6.3절 4·5).
10. 설정: 10-1 설정 파일 확장·언어·18세 확인, 10-2 칸 폭 기억·최근 검색어·블랙리스트 다시 받기, 10-3 다운로드 폴더·파일 이름 규칙, 10-4 이미지 디스크 캐시·비우기.
11. 배포: 11-1 버전 한곳·CI(두 플랫폼 검사), 11-2 라이선스 고지, 11-3 업데이터·정보 칸, 11-4 배포 워크플로·macOS 서명·공증·첫 초안 릴리스.

**2단계** 태그 동작·탭 → Pool → Set → 댓글/DText → 인기

**3단계** 필요한 것부터.
